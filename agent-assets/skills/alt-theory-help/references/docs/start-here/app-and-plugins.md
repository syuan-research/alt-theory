# The App and Plugins

Alt Theory the product comes in more than one form. Knowing which form
fits you takes one minute.

## The app

The desktop app is the whole product: the conversation interface, the
Understand/Work capability model, roles and knowledge bases, bundled
skills, approvals, imports, and settings — one install, no other tools
required. It is built for people who do not already live in an AI agent
harness, which is most researchers.

## Plugins for your existing harness

If you already work in an agent harness — Pi, Claude Code, or another —
you may not want a second application. The plugin form brings Alt Theory's
methods into the tool you already use:

- the **bundled skills**, unchanged — skills are universal across
  harnesses;
- an **agent definition** in your harness's own format, carrying Alt
  Theory's identity and principles;
- optionally, a **knowledge base** you place where your harness can read
  it.

What you get is Alt Theory's way of working — provenance-disciplined
search, alignment before big moves, plan records, restrained editing —
inside your own environment. What stays app-only is the product surface:
the mode switch, the approval interface, pickers, and imports, which your
harness provides in its own way.

[Plugins and Capability
Differences](../advanced/plugins-and-capability-differences.md) documents
the exact differences per harness, and which harness packagings are
currently available.

## What the app is built on

The app's agentic engine is [Pi](https://pi.dev), an open agent harness
with an active ecosystem. This is worth knowing even if you never touch Pi
directly, because it is why several good things are true:

- conversations are stored in a Pi-compatible format, so your work is not
  locked into Alt Theory;
- skills follow ecosystem conventions, so skills you install can work in
  both, and Alt Theory's skills can work elsewhere;
- conversations from other harnesses can be
  [imported](../system-guide/imports-and-continuity.md) and continued.

Alt Theory adds what a general harness does not have: the
understanding-first behavior, the research-oriented assets, and an
interface built for scholars rather than software engineers.

## Choosing

- Most readers: use the app. It assumes nothing and contains everything.
- Harness users who mainly want the methods: the plugin form.
- Both is a real option — the app for research conversations, the plugin
  where you already work. Your materials and skills can be shared between
  them; see [Shared Configuration, Skills, Models, and
  Assets](../advanced/shared-configuration-and-assets.md).
