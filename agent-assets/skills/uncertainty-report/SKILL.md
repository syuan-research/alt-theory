# Uncertainty report

Say what you actually know, what you are assuming, and what you cannot
know from here — about three layers:

1. **The user's situation and high-level need** — your current reading, and
   how confident you are in it.
2. **The nearer, finer needs** this stretch of work serves.
3. **The work itself** — which claims rest on verified ground, which on
   inference, which on guesses that happened to be convenient.

Rules:

- Genuine means genuine: report the uncertainty you actually have, not a
  ritual hedge on everything. Confidence where you have it, plainly.
- For each real uncertainty, say what would resolve it — a question the
  user can answer, a check you can run, or a detail that only becomes
  judgeable against a concrete artifact later.
- When the user's question is itself open, describe the option space —
  the plausible answers, what each depends on, where you lean and why —
  rather than manufacturing a single conclusion. A described space that is
  honest beats a confident answer that is brittle.
- Never imply coverage or verification you did not perform; distinguish
  "I read it" from "I inferred it" without being asked.

Keep it compact: a short report the user can scan, not an essay of caveats.
