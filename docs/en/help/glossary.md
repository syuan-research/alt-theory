# Glossary

The product's terms, defined once. Cross-references go to the canonical
page for each.

**Understand**: the capability mode for careful dialogue with bounded
reach: no command execution, no live network, no project folders. A
complete way to use the product, not a preview of Work.
[→ Understand and Work](../start-here/understand-and-work.md)

**Work**: the capability mode with practical reach: working folders,
live search and fetching, document production, commands, under visible
approvals.
[→ Understand and Work](../start-here/understand-and-work.md)

**Conversation**: the basic unit of working with Alt Theory: one thread
of discussion and action, with its own history, mode, model, and
materials. Durable, resumable, and portable.
[→ Conversations and History](../system-guide/conversations-and-history.md)

**Branch**: a related conversation split off from a message, carrying
everything up to that point, leaving the original intact. One of the
controls used to compare answers.
[→ Responses and Controls](../system-guide/responses-and-controls.md)

**Compare pane**: the 50/50 split of the center area opened after a
branch or same-prompt retry, so two versions of an answer can be read
side by side. BTW, helper, and subagent stay in the narrow rail instead.
[→ Responses and Controls](../system-guide/responses-and-controls.md)

**BTW**: a side conversation in a panel beside the main one, carrying
current context, for tangents.
[→ Responses and Controls](../system-guide/responses-and-controls.md)

**Helper**: the built-in assistant for questions about Alt Theory
itself. Starts fresh (does not read the current conversation) and
answers from current documentation.
[→ Helper and In-App Guidance](../system-guide/helper-and-guidance.md)

**Subagent**: a child conversation a lead delegates a bounded task to. It
runs as its own session at a clamped mode and a model tier that can be
lower, the same, or higher than the lead's; up to three concurrent.
`(planned)` skills (skill-button, role intensity) extend this layer but
are not yet coded.
[→ Agent Team and Subagent Sessions](../system-guide/agent-team-and-subagents.md)

**Working folder**: a folder on the computer attached to a Work
conversation; the place the agent can read and create files, and the
boundary of what it may modify.
[→ Working Folders, Files, and Paths](../system-guide/working-folders-files-paths.md)

**Knowledge base (KB)**: curated reference material, selectable per
conversation, that the agent consults to ground a discussion. Distinct
from a working folder.
[→ Knowledge Bases and Context](../system-guide/knowledge-bases-and-context.md)

**Role**: a selectable presentation layer: tone, pacing, teaching
style. Changes how the agent sounds, never its principles.
[→ Customization](../advanced/customization-without-changing.md)

**Soul**: the identity layer: the agent's worldview and principles,
which no role can override. A readable file, like everything else.
[→ Customization](../advanced/customization-without-changing.md)

**Skill**: a readable instruction file that shapes how the agent
handles a kind of task. Bundled skills carry the product's methods; the
user's own participate as equals.
[→ How Skills Work](../system-guide/how-skills-work.md)

**Skill-button** `(planned)`: a skill held on across several turns
rather than invoked once. The button darkens while active, then fades;
double-click locks it. Not yet in the interface or code.
[→ When Understanding Is the Goal](../using-the-app/when-understanding-is-the-goal.md)

**Command**: anything invocable by name from the `/` palette: skills,
plus conversation operations like /branch and /compact.
[→ Commands](../system-guide/commands.md)

**Toolbox**: the short menu of featured actions beside the composer; a
front door, not the full inventory.
[→ Toolbox](../system-guide/toolbox.md)

**Approval**: the request shown when an action crosses the
conversation's boundary (outside reads, network, installs). Deny is
always safe; silence counts as no.
[→ Permissions](../system-guide/permissions-approvals-agent-activity.md)

**Compaction**: the visible condensing of a long conversation's early
turns into a summary so the conversation can continue within the model's
context window.
[→ Conversations and History](../system-guide/conversations-and-history.md)

**Tombstone deletion**: deleting a conversation hides it from the list
but keeps the data on disk, recoverable until cleanup. The exception is
hosted private sessions, which are hard-deleted after a period of
inactivity.
[→ Conversations and History](../system-guide/conversations-and-history.md)

**Import**: bringing a conversation from another harness (Pi, Claude
Code, Codex, OpenCode, Grok Build) into Alt Theory as a normal,
continuable conversation, with losses labelled rather than papered over.
[→ Imports and Continuity](../system-guide/imports-and-continuity.md)

**Plugin**: Alt Theory's assets packaged for use inside another
harness: the bundled skills unchanged, plus an agent definition in that
harness's format carrying the product's identity.
[→ Plugins and Capability Differences](../advanced/plugins-and-capability-differences.md)

**Pi**: the open agent harness the app is built on. The reason
conversations, skills, and configuration follow ecosystem conventions
rather than proprietary ones.
[→ The App and Plugins](../start-here/app-and-plugins.md)

**Model / provider**: the AI model that powers a conversation, and the
service supplying it under the user's account. The app is
model-agnostic; choose per conversation.
[→ Models, Providers, and Access](../system-guide/models-providers-access.md)

**Provenance**: labelling every claim by where it came from: found now
(cited), model memory (marked unverified), or inferred (said so).
[→ Search, Sources, and Web Content](../system-guide/search-sources-web.md)
