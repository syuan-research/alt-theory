# 以理解为目标时

有时理解本身不是「真正工作」前的准备——理解就是工作。探索你可能投入一年的方向；弄清两个相近概念究竟在区分什么；在建基于某理论之前审视其假设；发展尚不属于任何单一项目的观点。

进入场景前先说明：本页讲的是*目标*，不是模式。以理解为中心的工作大多自然落在 Understand（理解模式），但也可在 Work（工作模式）中推进——例如需要实时文献检索时。本节三页描述的是工作类型；[模式选择](../start-here/understand-and-work.md)始终由你决定。

## 这类工作在这里是什么样

把未完成的东西原样带来。半成形的问题、相互矛盾的笔记页、你怀疑「承担了过多工作」的某个概念。智能体的职责不是快速收尾，而是帮你看清楚：

- **你的框架会被审视，而不只是被延伸。** 若问题把地方依恋与习惯混在一起，回复会区分二者，并说明每种框架会把你绑到什么承诺上——而不是默默选一个然后在上面搭建。
- **缺口保持可见。** 想法与证据未完全贴合处，会把错位摊开。智能体不会削掉理论棱角好硬套你的案例。
- **不确定性被标注，而不是被填满。** 主张会标明：既有且稳定、合理但未核实、或确实开放。需要实时来源才能核实时，智能体会明确说出来。
- **推进是分步的。** 你得到的是下一处有用的区分或问题，开放处附上现实可选路径——而不是你并未选择的完整框架。

## 如何塑造对话

对以理解为中心的工作，两个杠杆最重要：

- **知识库** 把策展领域材料放进智能体可及范围——当讨论应以此为根基时启用，并请智能体把你的想法连接到其中的具体来源。
- **角色（roles）** 改变呈现方式——更苏格拉底式或更直接，更辅导或更批判。没有角色会改动原则；更温和的语气也不会变成更「讨好」的智能体。

长期理解也值得有意保存。讨论到可暂歇处时，可请智能体做[对话摘要](../system-guide/bundled-skills.md)，或把正在成形的图景写入文件，使它不依赖单条对话存活。

## 核实在流程中的位置

理解型工作常擦到可核对事实——那项研究真的那么说吗？文献现状是否如此？在 Understand 模式中，智能体诚实处理且不做实时检索：它记得的内容会标为未核实（对引用尤其明确），支撑不住的绝不会编造。

当核实成为真正的下一步时，在同一条对话切到 Work：学术搜索返回真实、经 DOI 核验的文献与被引次数，页面可抓取并以来源引用。讨论从原处接上，但已站在经核对的地面上。纪律说明见 [搜索、来源与网页内容](../system-guide/search-sources-web.md)。

## 若你对 AI 的依赖比自己希望的多

学生常高度依赖 AI 建议，也清楚其中心风险：无论对错都显得可信，而导师未必有时间逐条核对。Alt Theory 不能替代指导，但比通用聊天工具更可被审查：

- 请它把支撑每条主张的东西分开——找到的、回忆的、推断的——它会照做。
- 问「什么会让这个框架错了？」它会当真问题处理，而不是趁机安慰你。
- 默认倾向是暴露论证中最弱一环，而不是抛光盖住——包括对自己的建议。

这样用时，工具会成为判断力的练习，而不是腐蚀判断力的替代品。
