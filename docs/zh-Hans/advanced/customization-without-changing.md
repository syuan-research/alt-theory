# 不改动 Alt Theory 的定制

人们对 Alt Theory 想改的大部分东西，并不需要碰应用本身。产品行为刻意承载在可读资产中——技能、角色、soul、知识库、模型配置——每一层都可由你扩展。

## 你自己的技能

最大的定制面，权威说明见
[添加与管理技能](../system-guide/add-and-manage-skills.md) 与
[共享配置](shared-configuration-and-assets.md)。简版：写 `SKILL.md`，放到共享或项目技能位置，若与内置方法重叠则设优先级。技能可编码从「我的学科如何引用」到完整分析工作流的一切。

## 角色

**角色预设**改变智能体如何呈现——语气、节奏、苏格拉底式还是直接、突出哪些思考动作。作为 markdown 文件加入应用的角色预设资产文件夹（kebab-case slug，按文件名选择）；会出现在角色选择器中。

使角色可自由书写的边界：角色改呈现，从不改原则。身份层（soul）明确高于任何角色——「要鼓励」的角色不能压过事实优先于附和。你可以写严苛批评者或耐心导师，而不会变成不同产品。

## Soul

**soul** 是身份层本身——世界观与原则。它像角色一样可选（「无」也可选），文件与其他一切一样在仓库中可读。写替代 soul 在机制上受支持，但会从根上改变产品性格——对多数定制目标，角色或技能才是对的工具，默认 soul 就是产品。

## 知识库

添加领域：在应用 KB 资产下创建 markdown 材料文件夹，即可在 KB 选择器中选。好知识库是策展的，不是倾倒的——智能体按判断查阅，信噪比决定查阅是否有用。领域元数据可声明范围与预期用途，便于智能体用得好。

## 自定义指令

按对话的常驻指令——你坚持的术语、领域要求的格式——可作为指令资产添加，在对话设置时选择，位于身份层与对话之间。

## 模型与提供商

任何兼容 API 的提供商都可在配置中添加——包括本地模型服务器，与
[隐私姿态](../system-guide/data-and-privacy.md) 自然组合：本地模型意味着对话内容不离开任何地方。模型条目声明应用会尊重的能力（如图像输入）。

## 界线在哪

以上一切都是数据：加入资产文件夹与配置的文件，升级安全且可分享。一旦你想要不同的*应用本身行为*——新工具、不同模式边界、UI 变更——你已越过定制，进入
[修改 Alt Theory](modifying-alt-theory.md)。
