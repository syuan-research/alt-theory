# 共享配置、技能、模型与资产

当 Alt Theory 与 Pi 或其他 harness 并存时，实践问题是归属（谁拥有哪份配置）、发现（从哪读什么），以及优先级（同名之物谁赢）。本页精确陈述三者。

## 归属（Ownership）

- **Alt Theory 拥有**：其模型/提供商/认证配置、应用设置（技能启用、优先级、自动标题）、内置资产（技能、soul、角色、知识库），以及对话数据。
  全部在自己的应用目录。
- **Alt Theory 不拥有但读取**：共享跨 harness 技能位置（`~/.agents/skills/`），以及已附加工作文件夹内的项目资源（项目技能、agent 上下文文件）。
- **Alt Theory 从不触碰**：其他 harness 的配置主目录。它不把运行时指向 Pi 的配置目录，也不同步。把现有 Pi/OpenCode 设置带过来是**一次性、有引导的迁移**——Helper 与你一起检查现有配置，可见地复制有用部分到 Alt Theory 自己的文件。

底层设计规则：就地读取生态资源，拥有自己的状态，从不镜像他人的。

## 发现

对话实际加载什么，按来源：

| 来源 | 加载什么 | 何时 |
|---|---|---|
| 内置（`agent-assets/`） | Alt Theory 技能、soul、角色、KB | 始终（受模式与启用约束） |
| 你的应用级启用 | 你按模式启用的外部技能 | 按技能设置 |
| 共享跨 harness 目录 | `~/.agents/skills/` 中的技能 | 启用时 |
| 已附加工作文件夹 | 项目技能（`.agents/skills/`、`.pi/skills/`）与项目上下文文件 | Work 模式，附加期间 |

每条对话在创建时精确记录加载了哪些资产及来源——使「为何那样表现」后来可答
（[检查](compatibility-updates-debugging.md)）。

## 优先级

两层机制：

1. **优先级设置**（全局，三选一）：优先 Alt Theory 内置技能、优先你的，或冲突时询问。默认：prefer-bundled。「冲突」指同类别方法——两个搜索技能、两个文档技能——不是任意两个技能。
2. **技能文本让位**：与设置无关，若干内置技能明确让位于同类别的用户安装技能（文档转换、页面抓取、搜索）——更丰富的领域替换正是预期情况。

对非技能资产无需解决冲突：模型配置是 Alt Theory 自己的；角色或 soul 是对话所选；项目上下文文件全部加载（它们描述不同事物，智能体像任何项目文档一样权衡）。

## 把你的技能与内置方法组合

认真定制设置的预期模式：

- 让**横切方法技能**（search-policy、aligning、plan-record、conventions）做它们的工作——它们刻意薄且领域中立。
- 用**你的领域技能**承载实质：你领域的文献实践、方法传统、写作约定。它们与方法层组合而不是打架——search-policy 管*诚实*，你的技能管*在你领域什么算好来源*。
- 当真不同意某内置方法时，替换它（优先级：优先你的），而不是绕开它。

## 模型

模型与提供商配置以 Pi 兼容文件存在 Alt Theory 目录内——格式共享，文件不共享。实践效果：提供商设置易于双向迁移（引导式迁移直接读 Pi 文件），为 Pi 写的模型定义复制后即可用，你在 Alt Theory 中做的任何事都不改变 Pi 安装使用什么。

### 两个目录，以及如何在其间移动

| | Alt Theory（本地应用） | Pi |
|---|---|---|
| 配置目录 | `~/.alt-theory/pi-agent/` | `~/.pi/agent/` |
| 提供商与模型 | `models.json` | `models.json` |
| 密钥与登录 | `auth.json` | `auth.json` |

Alt Theory 从不自行读取 Pi 目录。`models.json` 每个提供商一条——名称、Base URL、API 类型
（`openai-completions`、`openai-responses`、`anthropic-messages` 或
`google-generative-ai`），以及模型列表；`auth.json` 为每个提供商名保存凭证。两者都是普通可读 JSON。

**从 Pi 迁移提供商**（Helper 与你一步步做，而不是一次不透明搬迁）：

1. 读 Pi 的 `models.json` 中该提供商条目——名称、Base URL、API 类型，以及你实际用的模型。
2. 把同一条目加入 Alt Theory 的 `models.json`，或在「设置 → 模型」重填，后者写同一文件。
3. 从 Pi 的 `auth.json` 复制该提供商凭证到 Alt Theory 的，使用同一提供商名。
4. 从应用确认：提供商出现在「设置 → 模型」，对话可在其某个模型上开始。

任一步都不会回写 Pi。若提供商在 Pi 中通过登录流程而非密钥连接，在设置中重跑登录比复制令牌更可靠。
