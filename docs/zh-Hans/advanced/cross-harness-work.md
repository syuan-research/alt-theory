# 跨 harness 工作与连续性

Alt Theory 把对话当作可移植工作，而不是被俘获的数据。本页覆盖在应用与其他 agent harness 之间双向、深入地移动工作。

## 会话主体与 Pi 兼容

Alt Theory 对话以 Pi 的 JSONL 会话格式存储——应用刻意没有发明第二种转录格式。后果：

- 本地 Alt Theory 对话可导出为 Pi 可继续的形式，兼容的 Pi 会话也可进入；
- 转录比产品活得更久：对话历史在你磁盘上的文档化、广泛实现格式中，不是专有存储；
- *不是*对话的应用级东西——显示状态、研究记录、应用元数据——住在会话主体旁，不在其内，使主体保持干净便于交换。

## 导入，进阶用户想要的深度

[用户级页面](../system-guide/imports-and-continuity.md) 覆盖流程；这里是底层机制，在推边界时值得了解：

- **三种表示在每次导入中保持区分**：*可见转录*（人应看到的）、*活动上下文*（模型实际向前携带的）、以及*原始源证据*（其余一切，保留且可搜索，从不重放）。把它们混在一起就会编造历史；分离是 Alt Theory 不这样做的原因。
- **在任何东西存在前完整预检**：先解析并验证整个源；只有通过的投影成为会话。失败是结构化拒绝，点名记录与理由。
- **声明的转换**：每步有损操作与会话一起记录，转录中的占位符写明未重放什么。
- **按来源诚实**：例如加密的源压缩摘要不会解密或改写——续写从可读后缀开始并标注限制；谱系无法确定的源被拒绝而非猜测。子/子代理转录作为可搜索证据归档索引，不作为主历史重放。
- **重复导入分类**为未变（重新打开已有导入）或已变（新的托管副本）——变化的源从不合并进你的续写。

## 在别处继续应用对话

反向：在 Pi 中继续的 Alt Theory 对话保留对话主体，但留下应用层——Understand/Work 强制、批准 UI、应用资产是应用的事。agent 身份仅在你带来时旅行（见
[插件](plugins-and-capability-differences.md)）。向人或非 harness 工具交接时，markdown 摘要与 HTML 导出是正确载体——可读，但不是续写格式。

## 什么带走、什么留下，一表说清

| 事物 | 跨表面携带？ |
|---|---|
| 对话主体（轮次、工具、图像） | 是 — Pi 兼容 JSONL |
| 压缩摘要 | 是，源中可读时 |
| 技能 | 是，经共享技能位置（[细节](shared-configuration-and-assets.md)） |
| 模型/提供商配置 | 否 — 各工具自有；经引导式设置一次迁移 |
| 模式、批准、应用设置 | 否 — 应用层 |
| 应用级记录（显示状态、出处） | 留在应用副本 |

## 现实的多 harness 工作流

在一处想，在另一处做：导入分析成形的 Claude Code 会话，在 Understand 中用知识库审视，在工作文件夹的计划记录中发展设计，再回到编码 harness 继续实现——计划记录与任何文件在项目文件夹中，两边都可见。工作文件夹，而不是对话，是 harness 之间的自然共享地面；把持久状态放在文件里，任一侧都能捡起。
