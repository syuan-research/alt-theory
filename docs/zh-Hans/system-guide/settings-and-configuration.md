# 设置与配置

## 设置地图

**设置**收集应用级配置。按对话的选择——模式、模型、角色、知识库、工作文件夹——在对话本身，不在这里。

- **通用** — 界面语言（目前英语；中文计划中）、thinking 块显示等偏好。
- **模型** — 提供商、密钥与登录、模型条目及其能力。权威页：
  [模型、提供商与访问](models-providers-access.md)。
- **角色与知识库** — 可用角色预设与知识库，以及新对话默认值。

  **角色（role）** 是智能体的可选呈现层——语气、节奏、苏格拉底式还是直接——从角色选择器按对话选择（或不选 None，完全合理的默认）。角色改变智能体听起来如何，从不改变原则：身份层（**soul**）明确高于任何角色，因此更温和的语气不会变成更讨好的智能体。添加自己的角色：
  [定制](../advanced/customization-without-changing.md)。
- **技能** — 发现的一切、按模式启用，以及优先级设置。权威页：
  [添加与管理技能](add-and-manage-skills.md)。
- **自动标题** — 对话是否自命名，以及可选由哪个模型命名。

## 变更何时生效

处处一条规则：设置变更**立即保存**，但从不静默改写正在运行的对话。新对话自然接管；已打开对话在重新打开时接管。若变更不重启无法应用，应用会在变更当下说明。

## 谁拥有哪份配置

Alt Theory 处于生态中，因此值得精确说明谁配置什么：

- **应用拥有自己的模型、提供商与技能启用配置**，存在自己的本地目录。它不会持续镜像其他工具的配置；指向外来配置主目录也不是共享方式。
- **从生态中它*读取***：标准跨 harness 位置的技能，以及已附加工作文件夹中的项目资源。读取是发现，不是同步——源留在原处，归放置者所有。
- **工作文件夹贡献**其自身项目上下文与技能给附加到它的对话，仅在附加期间。
- **若你已用 Pi 或其他 harness**：现有设置可*迁移*——Helper 可与你一起检查现有配置，一次、可见地带来有用部分——而不是同步。跨这一切的优先级与组合规则：
  [共享配置与资产](../advanced/shared-configuration-and-assets.md)。

## 磁盘上在哪里

所有应用数据——配置、对话、记录——存在本机一个本地应用目录
（[是什么与在哪](data-and-privacy.md)）。进阶用户想要的两个事实：模型/提供商配置以 Pi 兼容文件存储；每条对话保留创建时所用资产与配置的精确记录，使设置变更后过去对话仍可解释。检查该记录：
[兼容性、更新与集成调试](../advanced/compatibility-updates-debugging.md)。
