# 模型、提供商与访问

Alt Theory 提供环境、方法与界面；AI 模型来自你配置的**提供商（provider）**。本页是该链路的权威说明。

## 模型芯片

输入区旁的模型芯片显示本对话使用的模型（以及已设置时的 thinking 级别）。悬停可看提供商与用量细节。点击可为当前对话切换模型——从下一轮起生效，对话不中断。

## Thinking 级别、上下文窗口与模型元数据

不同提供商宣告不同能力。Alt Theory 在每个模型条目上存储这些事实（经「设置 → 模型」，或写在 `models.json`）：

- **Thinking / reasoning 级别** — 输入区可提供的努力选项（例如 off / low / medium / high）。只有你启用的级别会出现在芯片中。若模型不推理，芯片会省略努力级别。
- **上下文窗口** — 对话大致 token 预算。提供商回报用量时，输入区旁的上下文环会用到它。
- **最大输出 token** — 模型条目有记录时，单条回复的软上限。
- **图像输入** — 模型是否在轮次中接受图像。

**Fetch model list**（提供商编辑器中、模型列表上方）是从提供商刷新 id 与能力标志的首选方式。提供商不暴露列表时（部分预设），请手工输入模型 id 并校正元数据，使输入区与上下文环保持诚实。

**新**对话的默认模型用「设置 → 模型」顶部的 **设为默认（Set as default）** 指定——在提供商编辑器内点选模型本身不会改变默认。（若尚无默认，保存第一个提供商时会把其第一个模型设为默认。）

## 设置提供商

配置在 **设置 → 模型**，同一界面也用作首次运行设置。支持两类访问：

- **API 密钥** — 来自 DeepSeek、Anthropic、OpenAI 或任何兼容端点。把密钥粘贴到提供商设置项；密钥本地保存在应用配置中，保存后不会再显示回来。
- **订阅登录** — 支持的提供商（目前 OpenRouter、xAI、OpenAI Codex）可通过各自登录流程连接，而不用密钥。

在至少一个提供商有效且激活之前，对话无法开始——应用会清楚拒绝，而不是在中途奇怪失败。你可以配置多个提供商与模型，并按对话选择。

若这些不熟悉，不必独自摸索：
[Helper](helper-and-guidance.md) 会用平实语言带你走完提供商设置——密钥从哪拿、放哪、如何确认可用。密钥属于设置，不属于聊天消息；若你粘贴进对话，智能体会帮你挪到正确位置，并建议不要在聊天中分享密钥。

更想先用通用聊天机器人起草文件？见
[用聊天机器人配置模型](configure-models-with-chatbot.md)。

### 配置实际在哪里

日常使用不必碰这些路径，但它们是设置界面背后的真相；若你已在跑 Pi，就更重要：

- 本地应用把模型配置放在 **`~/.alt-theory/pi-agent/`**
  （Windows 为 `%USERPROFILE%\.alt-theory\pi-agent`）：`models.json` 管提供商与模型，`auth.json` 管密钥与登录令牌。
- 它**不读取 `~/.pi/agent/`**。Alt Theory 不继承、不共享、不同步 Pi 安装的提供商配置——这种分离是有意的（[归属](../advanced/shared-configuration-and-assets.md#ownership)）。
- 文件在*格式*上与 Pi 兼容，因此两者之间搬配置是复制，不是转换。

**从 Pi 过来且那边提供商已可用**：要么在「设置 → 模型」再加一遍（一分钟，也最安全），要么请 Helper 对话协助迁移——它会与你一起查看现有配置，可见地复制有用部分，不碰 Pi 侧。
[共享配置与资产](../advanced/shared-configuration-and-assets.md)
是共享与否的完整说明。

## 费用与用量

模型使用由你的提供商按你的账户与其定价计费——应用不加价。为让用量可见，输入区旁的上下文环（见 [回复与控件](responses-and-controls.md)）显示对话的上下文占用，工具提示含 token 计数与提供商回报的累计费用。若担心意外费用：费用只在智能体实际回复或工作时累积；长时间无人值守任务正是值得瞥一眼可见费用数字的时候。

## 切换模型，以及什么会保留

- **对话中途切换**：随时允许；历史带过去。不同模型各有所长——把难的一轮换到更强模型是正常用法。
- **模型消失**（从你配置中移除，或提供商下线）：重新打开此类对话不会失败。应用回退到默认模型并可见说明；原选择会被记住，若模型回来，对话会重新拿到它。
- **图像能力**：模型是否接受图像记在模型配置中；见
  [文档、图像与其他输入](documents-images-inputs.md)。

## 核对

- 哪个模型在用：模型芯片，始终当前。
- 提供商是否工作：「设置 → 模型」显示各提供商状态；快速测试是发一轮一行的对话。

## 恢复：「我配了，但不工作」

按此列表往下查；多数情况能解决：

1. **提供商是否已保存且激活？** 草稿条目（未带有效密钥就保存）会存着但不可用。
2. **密钥是否有效且有余额？** 在提供商自己的控制台测试；过期试用与未充值账户是最常见原因。
3. **模型 id 是否仍有效？** 提供商会下线模型版本；查提供商的模型列表，不要猜。
4. **重启对话。** 配置变更作用于新建与重新打开的对话，不会在中途静默生效。
5. 仍卡住：[Helper](helper-and-guidance.md) 可与你一起检查配置状态，或见
   [故障排除](../help/troubleshooting.md)。
