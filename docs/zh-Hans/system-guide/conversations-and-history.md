# 对话与历史

## 对话列表

左侧面板列出你的对话，按工作文件夹分组，最近活动优先。在列表中你可以：

- **搜索**对话标题。
- **打开**对话以继续。
- 在行菜单中**重命名、删除或复制**对话——无需打开。复制相当于从对话末尾分支：独立副本共享完整历史，之后各走各的。
- 智能体活跃时，一眼看到每条对话的**状态**：运行中、完成但有未读结果、失败，或等待你的批准。

新对话在首次交流后自命名——简短生成标题会替换「首词占位」。重命名权始终在你；手动命名从不会被覆盖。

## 继续与改写

打开对话即完整恢复：历史、模式、工作文件夹、知识库与模型选择均会保留。你也可以重塑主线本身：

- **编辑或改写你较早的一条消息。** 对话从该点起用你的新表述继续；之后轮次从活动线移除。首次操作时应用会先说明这一点。改写用来修正把讨论带偏的框架——比重开对话更省事，也比与题外话纠缠更干净。
- **从任意消息分支**，在相关对话中探索替代路径，原对话保持完整。

各选项保留什么，见 [处理回复与对话控件](responses-and-controls.md)。

## 压缩：长对话如何继续

模型有有限的上下文窗口。对话接近上限时，应用会**压缩（compact）**：较早轮次被浓缩为模型继续携带的摘要，对话继续。

你看到并控制的：

- 压缩是**可见的**：分隔线标记边界，摘要就在那里、可展开——你能读到模型现在实际携带什么。
- 运行时有**状态**，可停止；对话仍可用。
- 可在自然暂歇点用 `/compact` **主动触发**，而不必等到极限。

压缩对工作的含义：摘要忠实但有损。应用自身立场是：关键事实不应只活在转录里——决策应写入[计划记录](bundled-skills.md#adaptive-plan-record)或工作文件夹中的文件，它们从不被压缩。若很久以前陈述的事实很重要，而压缩后的回复似乎丢了它，请重述或指向持有该事实的文件；另见 [搜索、来源与网页内容](search-sources-web.md) 中的诚实规则——智能体被指示应标记而非臆造它已不再拥有的内容。

## 导出与分享对话

把对话拿出去是一等公民操作，两种形式对应两种目的：

- **给人阅读与分享** — [对话摘要或交接说明](bundled-skills.md#conversation-summary)
  为 markdown，或转录的 HTML 导出：导师或合作者无需特殊工具即可阅读。
- **在别处继续** — 对话底层的 Pi 兼容文件，生态中的其他 harness 可拾起并继续。细节：
  [跨 harness 工作](../advanced/cross-harness-work.md)。

## 核对

- **我在哪条对话，附加了什么？** 输入区显示当前工作文件夹、知识库、模型与模式。
- **对话存在哪里？** 列表按工作文件夹分组；对话数据本身存在本地——
  见 [你的数据与隐私](data-and-privacy.md)。

## 恢复

- **一轮被中断**（停止、崩溃、网络）：对话仍可用；已完成动作记在转录中。
  继续，或改写被中断的请求。
- **重新打开后看起来不对**（缺尾、状态异常）：刷新一次；若仍有问题，见
  [故障排除](../help/troubleshooting.md)，并说明对话大致年龄，以及是否导入或压缩过。
- **误删对话？** 列表删除意在移除——请视为最终。若很重要，在本地做其他事之前先联系
  [版本与进一步帮助](../help/releases-and-further-help.md) 中的支持渠道。
