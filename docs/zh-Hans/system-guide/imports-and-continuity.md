# 导入、交接与跨 harness 连续性

你在其他 AI 工具中已做的工作不必留在那里。Alt Theory 可从其他 agent harness 导入对话并作为自己的继续——离开时也可向外交接。

## 导入对话

支持的来源：**Claude Code、Codex、OpenCode、Grok Build**。
（Pi 格式会话是 Alt Theory 自身原生格式，可直接带入——见 [跨 harness 工作](../advanced/cross-harness-work.md)。）
导入入口出现在产品该出现的地方：创建对话时的空状态，以及导航菜单。

流程：

1. **发现** — 应用在本机找到源工具的对话并列出，可搜索，最近优先。
2. **预览** — 在创建任何东西前，完整检查所选对话，并展示导入将携带什么。
3. **导入** — 对话变成普通 Alt Theory 对话：可读历史、可继续，列表名标明来源。

源工具中任何东西都不会被修改。导入只读，从不回写。

## 什么忠实导入——什么不装假

导入的对话是忠实但诚实的投影：

- **携带**：你的消息与助手消息、工具活动、可恢复时的图像与附件，以及源以可读方式存储时对话自身的压缩摘要。
- **标注，不伪造**：源记录了但导入无法重放的内容（不可导出的附件、提供商私有状态）以标注占位符出现，写明那里曾是什么。完整源记录作为可搜索证据与对话并置保存。
- **拒绝，不编造**：导入器无法如实表示的源对话——历史含糊、无法识别的内容——会说明理由拒绝。从不做看似合理的重构。

给定导入转换了什么的完整列表与对话一起存储，智能体从该记录回答「导入丢了什么？」，而不是猜。

## 继续导入的对话

第一轮表现会像你希望同事那样：接上线。智能体把导入上下文当可用上下文——且因世界可能在导入后变动，它在真正动手时的第一步是**读你当前文件**，再就看起来已变动的具体事项发问（计划步骤已完成、文件日期晚于导入），而不是用免责声明或「告诉我改了什么」迎接你。

对之后又有变化的源对话重新导入会创建**新副本**——从不合并进或覆盖你已有的 Alt Theory 续写。

## 向外交接

连续性双向：

- **对话摘要与交接说明** — 索取一份
  （[内置技能](bundled-skills.md#conversation-summary)）；落地为出处处理顺的 markdown 文件，合作者、导师或其他工具可读。
- **Pi 兼容会话** — 对话以 Pi 格式存储；可在 Pi 中继续再回来。深入说明：
  [跨 harness 工作](../advanced/cross-harness-work.md)。

## 核对 / 恢复

- **这次导入携带了什么？** 问智能体，或查对话的导入记录——两者来自同一份存储列表。
- **我的对话未出现在导入列表**：源工具的数据须在本机；检查来源是否支持（上表），并见 [故障排除](../help/troubleshooting.md) 的分源说明。
- **导入被拒绝**：显示的理由是真实原因——通常源自身记录在某处不完整或含糊。导入器不能猜；源对话仍完整留在原处。
