# 添加与管理技能

## 安装技能

没有应用商店，也没有安装仪式——技能就是可读文件组成的文件夹，安装就是放到应用会查找的位置：

- **给所有工具用**（推荐）：主目录下的跨 harness 技能文件夹
  `~/.agents/skills/<skill-name>/`。此处的技能会被 Alt Theory 与遵循同一约定的其他 harness 发现。
- **在项目内**：工作文件夹中的 `.agents/skills/`（或 `.pi/skills/`）——附加该文件夹时技能生效（Work 模式），并随项目走。

技能文件夹包含描述用途与做法的 `SKILL.md`；可选更多参考文件。格式就这些。你可以用一个下午自己写一个——或请智能体根据你的实践起草，这是真正不错的早期项目。

技能从哪来很重要：技能是智能体会遵循的指令，因此只安装你读过或信任的，就像对待任何准备照做的建议。

## 启用与作用范围

**设置 → 技能** 列出发现的一切——内置、你的、项目的——并控制在哪里加载：

- 启用是**按模式**的：Understand 与 Work 有各自启用集，因为能力边界不同。Understand 在你选择前不从外部技能起步；Work 的默认集更广——两套都可由你改。
- 变更立即保存，但从不静默改写正在运行的对话：新对话自然使用新选择，已打开对话在重新打开时接管。

## 优先级：你的技能与内置技能重叠时

**技能优先级**设置（设置中）是一个全局选择：

- **优先 Alt Theory 内置技能**（默认）——除非你另说，产品方法生效；
- **优先我的技能**——你的同类别技能胜出；
- **问我**——冲突在对话中作为问题出现。

与设置无关，若干内置技能会明确让位于同类别的用户安装技能（文档转换、页面抓取、搜索）——更丰富的领域版本正是用户常带来的。多 harness 组合与细规则见
[共享配置与资产](../advanced/shared-configuration-and-assets.md)。

## 核对

- **本对话哪些技能激活？**「设置 → 技能」显示启用集；对话中技能使用以具名技能行可见——问「你当前有哪些技能？」可得到实时列表。
- **新技能被发现了吗？** 应用重新扫描后出现在「设置 → 技能」（重新打开设置，或首次安装后重启应用）。

## 恢复

- **技能从不触发**：从[命令面板](commands.md)按名称显式调用——显式调用总是有效。
  然后检查其 `SKILL.md` 描述：触发按该描述匹配，描述未覆盖你的措辞就不会触发。
- **错误的技能胜出**：检查优先级设置，以及两技能是否真属同一类别（无关技能不冲突——两者都加载）。
- **项目技能缺失**：确认包含它的文件夹已附加到本对话，且对话在 Work 模式。
