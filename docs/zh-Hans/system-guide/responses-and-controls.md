# 处理回复与对话控制

这些控制的核心用途是对照。大语言模型易于附和、对措辞敏感、且基于采样，单一答案不足以信任：需要看到答案在改变提示、提问角度或模型时是否变化。编辑、同提示重试与分叉都生成一份与原版等宽并列的版本，不干扰原版。

## 上下文环

输入框旁的环显示本场对话已用上下文窗口的比例。提示分解输入输出 token、缓存使用与提供方报告的费用。当环接近填满时，压缩是让对话继续的方式（[见对话与历史](conversations-and-history.md)）。

## 运行中的引导

智能体运行时你发送的文本作为引导消息送达，而非以忙为由拒绝。它会在下一步边界处被看到，与 Pi TUI 中轮次运行时的输入方式一致。

## 生成可对照的版本

编辑、同提示重试与分叉都会在原版旁以等宽位置开启新版本，原版永不被修改。没有确认对话框：这些操作都不破坏原内容。

- 编辑你早先的一条消息：以新措辞从该点重跑讨论。用于测试同一问题的不同提问角度是否改变答案。
- 重试在原位重跑一次失败或空白的尝试，输入框上方。它不开启侧版本，用于恢复，不是对照。
- 再次试同一提示以兄弟版本重跑同一提示。用于了解同一输入下运行之间的差异。
- 分叉从任意消息开启一场相关对话，携带到该消息为止的全部内容。用于在同一累积上下文中推进不同方向。

要一次比较同一任务的两支以上，用工作台 A/B 对照界面，而不是堆叠分叉。

## 侧边对话

- 顺带（BTW）开启携带当前上下文的侧边对话，用于不该干扰主线的旁支。
- 助手以全新视角开始，不读取你的讨论，用于应用相关问题（[详情](helper-and-guidance.md)）。
- 牵头对话可把有边界任务委派给子代理，作为独立会话运行（[详情](agent-team-and-subagents.md)）。

侧边对话共用对话样式，但停在一个窄面板中，它们不占 50/50 对照位置，该位置仅用于分叉、编辑与同提示重试。

## 把侧边对话加入列表

分叉、顺带、助手或子代理可作为独立首类对话加入对话列表。其来源保留为标签（Branch、From BTW、From subagent 等），而非改名。这取代了早期的「提升」操作。
