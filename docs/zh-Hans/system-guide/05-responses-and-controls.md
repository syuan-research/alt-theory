# 处理回复与对话控制

这些控制的核心用途是对照。大语言模型易于附和、对措辞敏感、且基于采样，单一答案不足以信任：需要看到答案在改变提示、提问角度或模型时是否变化。「编辑并比较」会生成一份侧置版本，不干扰原版。

## 上下文环

输入框旁的环显示本场对话已用上下文窗口的比例。提示分解输入输出 token、缓存使用与提供方报告的费用。当环接近填满时，压缩是让对话继续的方式（[见对话与历史](01-conversations-and-history.md)）。

## 运行中的引导

智能体运行时你发送的文本作为引导消息送达，而非以忙为由拒绝。它会在下一步边界处被看到，与 Pi TUI 中轮次运行时的输入方式一致。

## 生成可对照的版本

铅笔按钮的含义是「编辑并比较」。编辑留在原用户消息气泡内，原版永不被修改，也没有确认对话框。

- 直接发送编辑，会继承当前模型与角色并在兄弟对话运行。
- 选择「先调整模型或角色…」，会先打开兄弟对话，编辑后的问题仍留在输入框中；是否真的修改配置由你决定。
- 「重试」会在同一对话中把最新用户消息从头再跑一次，包括误点停止后的情况；它不产生右侧或列表分支。
- `/branch` 从当前上下文打开一个尚未发送消息的传统分支。

要一次比较同一任务的两支以上，用工作台 A/B 对照界面，而不是堆叠分叉。

## 侧边对话

- 顺带（BTW）开启携带当前上下文的侧边对话，用于不该干扰主线的旁支。
- 助手以全新视角开始，不读取你的讨论，用于应用相关问题（[详情](16-helper-and-guidance.md)）。
- 牵头对话可把有边界任务委派给子代理，作为独立会话运行（[详情](14-agent-team-and-subagents.md)）。

右侧相关对话与中间共用思考、工具、技能、审批、slash command 与历史显示，并可选择模型和角色；为节省空间暂不显示 mode。顺带、助手和子代理保持窄面板，分支与编辑比较使用较宽的对照面板。

## 把侧边对话加入列表

分叉、顺带、助手或子代理可作为独立首类对话加入对话列表。其来源保留为标签（Branch、From BTW、From subagent 等），而非改名。这取代了早期的「提升」操作。
