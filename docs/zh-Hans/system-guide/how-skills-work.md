# 技能如何工作

**技能（skill）** 是可读的指令文件，塑造智能体如何处理某类任务——何时搜索、如何引用，如何编辑接近定稿的文本，如何组织它创建的文件。技能是 Alt Theory 方法的打包方式：透明、可检查、可替换。

## 为何用技能，而不是隐藏调参

技能做的一切都写在技能文件里，用平实语言。你可以打开任意技能，读到智能体究竟被吩咐了什么。由此有三个值得在意的后果：

- 你可以**审计**你注意到的行为背后的方法；
- 你可以**添加**自己的技能，并以平等身份参与；
- 技能遵循生态惯例，因此可以**迁移**——更广智能体生态的技能在这里可用，Alt Theory 的技能也可在其他 harness 中用。

## 技能从哪来

三个来源，都在设置中可见：

- **内置（Bundled）** — 随产品发布；承载其方法
  （[目录](bundled-skills.md)）。
- **你安装的** — 放在本机标准技能文件夹
  （[如何](add-and-manage-skills.md)）。
- **项目技能** — 住在你附加的工作文件夹内；随项目来去（Work 模式）。

## 技能如何激活

两条路径：

- **按匹配。** 每个技能声明自己用途。当你的请求匹配时，智能体加载并遵循该技能。这是判断，不是关键词魔法——按含义匹配描述。
- **显式。** 从[命令面板](commands.md)按名称调用任意技能，或通过其
  [Toolbox](toolbox.md) 入口。当你要应用特定方法时，显式调用是可靠路径。

加载技能是**可见的**：回复中有一行点名所用技能——不会伪装成普通读文件。若你预期技能会触发却没有，按名称调用总是有效；发现漏触发值得
[报告](../help/releases-and-further-help.md)。

## 技能与模式

仅作指令的技能（如何对齐、如何编辑）两种模式都可用。方法需要工具的技能——实时搜索、页面抓取、文档转换——是 **Work 专用**，因为 Understand 刻意没有命令执行。[模式页](../start-here/understand-and-work.md)
说明边界；每个内置技能条目会写明它在哪一侧。

## 技能重叠时

你可能安装与内置技能覆盖同一领域的技能——更丰富的文档技能、你学科的搜索实践。谁优先由你设定：**优先级设置**可选 prefer-bundled（优先内置）、prefer-yours（优先你的）、或 ask-each-time（每次询问）；若干内置技能还会按自身文本让位于同类别的用户安装技能。权威细节：[添加与管理技能](add-and-manage-skills.md)；
进阶组合策略：
[共享配置与资产](../advanced/shared-configuration-and-assets.md)。
