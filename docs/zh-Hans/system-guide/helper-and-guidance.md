# Helper 与应用内指引

你正在读的文档是学习应用的一种方式。另一种内置：应用在值得解释的时刻解释自己。

## Helper（帮助助手）

**Helper** 是回答关于 Alt Theory 本身问题的旁线对话——某功能如何工作、设置在哪、为何某行为如此，以及提供商、密钥与工具安装的引导式设置。

两个定义性性质：

- **从干净状态开始。** Helper 不读取你当前对话。这既是尊重隐私的默认，也使它随处可复用——空白界面与项目中途是同一助手。（*应当*携带你上下文的题外话，请用
  [BTW](responses-and-controls.md)；选择时应用会说明这一区别。）
- **依据当前文档作答。** Helper 自身规则要求对任何具体或会变的内容查阅产品当前文档——并说明未能核实什么，而不是凭记忆编步骤。诚实的「我无法确认，请看这里」按设计在其词汇里。

从 Toolbox 打开（「问 Alt 怎么用，或修设置」）。若 Helper 交流对项目变得重要，可提升为分支，变成普通对话。

## 引导式设置

设置任务——缺工具、要配置的提供商、期刊访问的可选浏览器档——经
[setup-helper 技能](bundled-skills.md#setup-helper) 用平实语言运行：
将安装什么、让你能做什么、有多大，然后你的 yes/no，再核实是否真的生效。从不静默安装；拒绝安装时，若有无安装替代方案会给你。

模式说明：*解释*设置随处可用——Helper 在任何对话中回答配置问题。*执行*安装是行动，因此在具备 Work 能力的对话中运行；若从 Understand 询问，会被指向切换，而不是卡住。

## 在正确时刻教

应用避开入门的两个极端——没人读的导览，与没人找到的功能：

- **一次性说明**在你首次使用会改写历史的动作时出现（改写消息、首次分支）——短通知，一次。
- **轮换提示**在你已在等待时（思考或长工具运行中）露出一行能力——零成本、不打断。
- **命令面板自我教学** — 键入 `/` 就是应用自己的索引。

## Helper 不够时

Helper 了解产品；它不了解你的缺陷。问题见
[故障排除](../help/troubleshooting.md)；限制见
