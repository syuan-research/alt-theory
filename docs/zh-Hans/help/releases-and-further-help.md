# 版本与进一步帮助

## 读懂发布线

Alt Theory 版本名携带成熟度：`-alpha` 标签表示活跃开发——可用、已在真实研究中使用，且仍在变动。仓库变更日志用平实语言记录每次发布改了什么，版本说明解释编号。alpha 对兼容性意味着什么——什么受保护（你的数据，始终）以及什么仍可能变（资产、界面）——在
[兼容策略](../advanced/compatibility-updates-debugging.md) 中精确陈述。

更新前，变更日志值得扫一眼；更新后，重新打开最近对话，任何回退通知会告诉你所依赖的东西是否移动了。

## 获取帮助，按远近顺序

1. **应用内 Helper** — 怎么做、在哪里、引导式设置、平实解释。依据当前文档作答，并说明无法核实什么。
2. **这些文档** — 权威功能页
   （[系统指南](../README.md#system-guide)）、按问题组织的帮助
   （[故障排除](troubleshooting.md)）、边界
   （[已知限制](compatibility-formats-limitations.md)）。
3. **仓库** — `github.com/syuan-research/alt-theory`：源码、变更日志与 issue 跟踪。

## 报告缺陷

alpha 产品以好报告的速度改进。有用的报告包括：做了什么、发生了什么、期望什么、应用版本与平台，以及涉及的对话是否导入或压缩过。
[分流步骤](troubleshooting.md#is-it-a-configuration-problem-a-provider-limitation-or-a-bug)
帮你归到正确问题类型——而「行为不诚实」（未标注主张、编造引用、静默替换）在这里始终是缺陷报告，绝不是吹毛求疵。

## 反馈与研究计划

Alt Theory 也是长期研究努力：学者究竟需要何种 AI 支持，我们如何知道？当前产品体现暂定答案，不同意见是有用数据。若你想超出「使用工具」——它辜负你的难案例、研究合作，或参与研究——经仓库联系项目。带上困难例子；那就是邀请。
