# 应用与插件

Alt Theory 产品不止一种形态。花一分钟弄清哪种适合你即可。

## 应用（App）

桌面应用是完整产品：对话界面、Understand/Work 能力模型、角色与知识库、内置技能、批准、导入与设置——一次安装，不依赖其他工具。面向并未日常泡在 AI 智能体 harness 里的人，也就是大多数研究者。

## 给已有 harness 的插件

若你已在某种 agent harness（Pi、Claude Code 等）中工作，未必想再开第二个应用。插件形态把 Alt Theory 的方法带进你已有的工具：

- **内置技能（bundled skills）** 不变——技能跨 harness 通用；
- 以你的 harness 自身格式提供的 **agent 定义**，承载 Alt Theory 的身份与原则；
- 可选：把 **知识库** 放在 harness 能读到的位置。

你得到的是 Alt Theory 的工作方式——有出处纪律的搜索、大动作前对齐、计划记录、克制编辑——在你自己的环境里。仍属应用独占的是产品表面：模式切换、批准界面、各类选择器与导入；这些由 harness 以自己的方式提供。

[插件与能力差异](../advanced/plugins-and-capability-differences.md) 记录各 harness 的确切差异，以及当前可用的打包形式。

## 应用建立在什么之上

应用的智能体引擎是 [Pi](https://pi.dev)，一个开放的 agent harness，生态活跃。即便你从不直接碰 Pi，了解这一点仍有用，因为由此带来若干好处：

- 对话以 Pi 兼容格式存储，工作不会被锁死在 Alt Theory 里；
- 技能遵循生态惯例，你安装的技能可两边用，Alt Theory 的技能也可在别处用；
- 其他 harness 的对话可以[导入](../system-guide/imports-and-continuity.md)并继续。

Alt Theory 补上通用 harness 没有的部分：以理解为先的行为、面向研究的资产，以及为学者而非软件工程师设计的界面。

## 怎么选

- 多数读者：用应用。不预设你已有任何东西，且功能齐全。
- 已有 harness、主要想要方法的人：用插件形态。
- 两者并用也完全合理——研究对话用应用，你已在工作的地方用插件。材料与技能可共享；见 [共享配置、技能、模型与资产](../advanced/shared-configuration-and-assets.md)。

# 带入你的材料与上下文

研究对话总是「关于」某些东西——笔记、草稿、数据、论文。本页是把材料带进来所需的最少知识。

## 一屏说清各部分

- **对话（conversation）** 是你与智能体思考和做事的地方。它保留自己的历史与配置。
- **文件附件（file attachment）** 把某个具体文件放到智能体眼前——拖进输入区或用附加按钮。
- **工作文件夹（working folder）**（Work 模式）是本机上智能体可在其中工作的文件夹：读文件、创建新文件。附加文件夹是有意为之——它定义实践工作发生在哪里。
- **知识库（knowledge base）** 是策展过的参考材料——在相关领域启用后，智能体可查阅。

它们可自然组合：一条对话可能附加了你的草稿、以项目文件夹为工作文件夹，并启用某个知识库——也可以什么都没有。

## 智能体看见什么，以及如何核对

智能体看到你带进对话的内容——附件、工作文件夹内容、已启用的知识库——以及你写的文字。它看不到电脑上其余部分。若不确定当前附加或启用了什么，输入区会显示本对话的工作文件夹与知识库；你也可以直接问智能体——「你现在能看见什么？」是正常问题，答案会说明它实际读过哪些文件，而不是含糊保证。

## 真实文件，认真对待

Alt Theory 能读研究里真正会用到的格式——Word、PDF、Excel、PowerPoint——转换副本会与原件并排放置，文件名带 `_converted` 后缀，配对关系一目了然。

入门页也值得写明的一条约定：**原文件从不被原地修改。** 智能体修订文档时，会在副本上工作或生成命名清晰的新文件，并告诉你写到了哪个文件。文件始终是你的。

## 完整说明在哪里

- 文件夹与路径：[工作文件夹、文件与路径](../system-guide/working-folders-files-paths.md)
- 知识库：[知识库与上下文](../system-guide/knowledge-bases-and-context.md)
- 格式与图像：[文档、图像与其他输入](../system-guide/documents-images-inputs.md)

# 继续、转向与之后再回来

真正的研究工作不是线性的：会暂停、分叉、回退，几周后再捡起。Alt Theory 的对话就是为此设计的。

## 对话是持久的

每条对话都保存在本地，出现在对话列表中，可按工作文件夹分组并搜索。首次交流后对话会自命名；随时可改名。重新打开任意对话即可继续——上下文、材料、模式与配置会一并恢复。

## 改方向，而不丢掉任何东西

你不只是「接着走」或「重来」：

- **Stop（停止）**——随时中断回复并转向。
- **编辑或改写**你较早的一条消息——对话从该点起用你的新表述继续。首次这样做时，应用会说明会重写什么。
- **Branch（分支）**——分出一条相关对话去试替代路径，原线保持完整。
- **BTW（旁白/旁线）**——打开携带当前上下文的小旁线对话，处理不该弄乱主线的题外话。若旁线后来变得重要，可提升为完整分支。

每种选项保留的东西不同；对照表见 [处理回复与对话控件](../system-guide/responses-and-controls.md)。

## 长对话仍能继续

长研究对话终会超过模型一次能看全的范围。临近时，应用会**压缩（compact）**对话：较早轮次被摘要，以便工作继续。这是可见的，不是静默的——有分隔标记边界，摘要可展开阅读。若某段关键内容绝不能因摘要丢失，请写入文件或计划记录；文件不会被压缩。细节见 [对话与历史](../system-guide/conversations-and-history.md)。

## 隔一段时间再回来

隔几天或几周重新打开对话时，恢复的是对话本身——历史、工作文件夹、知识库、模式。关于对话外的世界，有两点要诚实说明：

- 若期间工作文件夹被移动或改名，应用会告知并让你重新指定，而不是假装无事。
- 若文件自上次工作后有变化，智能体在真正动手前会先读当前文件——而不是迷信记忆里的旧版本。

这是产品的一贯姿态：回来应该成本很低，对话里关于项目的说法应与项目现状一致。

# 开始第一次对话

## 空白界面

新对话从简洁界面开始：一句问候、两张**模式卡片**——Understand（理解模式）与 Work（工作模式）——以及消息输入区。输入区周围还有：

- **模型芯片（model chip）**，显示本对话将使用的 AI 模型；
- **角色选择器（role picker）**，可选呈现风格——不选也完全没问题（[角色是什么](../system-guide/settings-and-configuration.md)）；
- **知识库选择器**，可选策展参考资料；
- **Toolbox（工具箱）**，应用中重点能力的小菜单。

此刻不必配置这些。默认值已经让第一次对话能直接跑起来。选 **Understand**——认真对话、不碰你的文件——然后开始输入。

## 值得发出的第一条提示

Alt Theory 最擅长处理真实、尚未成形的思考——那种因为不够完整、你可能犹豫要不要问同事的问题。例如：

> 公园改造后人们使用方式为什么会持续变化，我感兴趣，但分不清自己的问题究竟关于地方依恋、习惯，还是别的。你能帮我弄清我真正在问什么吗？

通用聊天机器人往往会直接塞给你一个框架。Alt Theory 更可能放慢节奏：区分相近概念、问你观察到了什么、指出每种框架会把你绑到什么承诺上，并标明自己不确定之处。这种更慢的推进，正是产品按设计在工作。

## 你眼前会看到什么

智能体回复时，视对话情况你可能看到：

- **Thinking（思考）**——可折叠块，展示模型作答前的推理。
- **工具行（tool lines）**——智能体读文件、搜索或使用技能时的一行记录，让动作可见而非隐晦。
- 回复正文，在智能体使用表格与图示时会渲染出来。

可随时用停止控件**中断**回复——不会弄坏任何东西，对话从你下一步怎么走继续。

## 若你还不熟悉 AI 智能体工具

从第一分钟起值得知道两件事：

- 在 Understand 模式下，智能体不能访问网络，也不会碰你未附加的文件——越界操作会先问你。你粘贴或附加的内容才是它能看到的。
- 这里没有不可逆的操作。对话可以停止、改向、回看、之后再续——见 [继续、转向与之后再回来](continue-and-return.md)。

# 安装与启动 Alt Theory

Alt Theory 在本地电脑上运行。获取方式有两种。

## 打包好的应用

打包桌面版目前直接提供给测试者与合作者。支持的平台：

- **macOS**（Apple Silicon）
- **Windows**（x86）

其他平台组合未经测试，也不作承诺。

首次启动时，操作系统可能会提示「未识别的开发者」——在应用商店之外分发的软件常见如此。macOS 上请首次右键应用并选择「打开」；Windows 上在 SmartScreen 对话框中选「更多信息 → 仍要运行」。若不想走这一步，可改用下方从源码构建的方式，完全避开该提示。

## 从仓库构建

完整源码已公开。安装较新的 Node.js 与 npm 后：

```bash
git clone https://github.com/syuan-research/alt-theory
cd alt-theory
npm ci
npm --prefix alt-theory-app/frontend ci
npm run build:frontend-v6
```

然后用对应平台的启动脚本启动本地应用（当前命令见仓库 README）。应用会提供本地 Web 界面并在窗口中打开；不会托管到任何远端。

## 首次启动

第一屏就是应用本身——一条等待开始的对话。唯一需要先搞定的是：至少配置一个**模型提供商（model provider）**。Alt Theory 提供工作区与方法，模型由你接入。

- 若应用来自 Alt Theory 团队，提供商可能已配好——直接开始输入即可。
- 否则，首次运行设置会引导你添加提供商：填入你使用的 API 密钥，或通过支持的订阅登录。[模型、提供商与访问](../system-guide/models-providers-access.md) 覆盖全部选项；应用内 [Helper（帮助助手）](../system-guide/helper-and-guidance.md) 也能用平实语言逐步引导。

提供商就绪后即可开始：

# 理解模式与工作模式（Understand / Work）

每条 Alt Theory 对话都运行在两种模式之一。区别不是「聊天对智能体」——两种模式都是智能体式的。区别在于：你向智能体开放了多少本机与工具生态。

## Understand（理解模式）

Understand 面向认真对话，并刻意收窄触达范围。

- 智能体在对话本身、你附加的文件、所选知识库，以及它自身知识上工作——并清楚标注来源性质。
- 它不浏览网页、不跑命令、也不在你的文件系统里四处走动。
- **Understand 中没有实时检索，这是设计如此。** 当某项主张需要核实时，智能体会说明这一点，并给出当前最佳理解，按扎实程度标注——既有知识、合理但未核实、或确实未知。它不会把记忆包装成「搜到的结果」。

Understand 是使用 Alt Theory 的完整方式，不是 Work 的阉割预览。若你主要用产品来思考、审视与讨论，可能大部分时间都在这里。

## Work（工作模式）

Work 保持同样的对话标准，并加上实践触达：

- **工作文件夹**（working folder，可选更多文件夹），智能体可在其中读写项目文件；
- **实时搜索与抓取**——通用网页、带可核验元数据的学术检索，以及整页抓取；
- **文档工作**——阅读 Word、PDF、Excel、PowerPoint，并生成新文档；
- **命令与安装**，始终经过可见的批准流程。

Work 不是「不再认真思考的生产力模式」。它把同一标准带进行动：有后果的选择会说明理由，保留出处，且**从不原地改写你的原文件**。

## 什么会请求许可

在 Work 模式下，有些事在你设定的边界内，有些事总会询问：

- 在你附加的工作文件夹内，智能体可逐步推进而无需每一步打断你。
- 读取这些文件夹之外、超出内置搜索工具的网络访问、以及安装任何东西——会弹出**批准请求（approval request）**，写明请求内容与你授予的权限。拒绝是安全的；对话会继续。

完整说明见 [权限、批准与智能体活动](../system-guide/permissions-approvals-agent-activity.md)。

## 切换模式

可随时在 Understand 与 Work 之间切换。切换从你下一条消息起生效。对话、推理、已附加材料，以及角色与知识库选择都会带过去——切换不会分叉或重置任何东西。

自然节奏往往是：在 Understand 里想清楚，直到下一步不再只是多聊几句，再切到 Work 去搜索、核实或产出，当动手暴露出概念问题时再回来。[使用 Alt Theory 应用](../README.md#using-the-alt-theory-app) 一节用真实研究场景展示这一节奏。

## 一句话怎么选

想只要思考、别的都不动时选 Understand；希望对话能碰到你的文件与实时外部世界时选 Work——答案变了就切换。

# Alt Theory 是什么

Alt Theory 是面向社会科学的研究工作区。核心是与一位认真对待思考的 AI 协作者对话：它区分已知与推断，标出不确定性而不是遮掩，宁可告诉你无法核实某事也不愿编造引用。当工作从思考推进到动手——检索文献、阅读与产出文档、在真实项目文件中推进——同一条对话也能承担那部分工作。

## 认真思考是底线

多数 AI 工具被调成尽快给出自信、抛光的答案。对研究而言，这种速度有代价：看似合理的答案可能藏起概念跳跃、缺失证据，以及你未考虑的替代路径。Alt Theory 反其道而行。其默认行为是：

- 暴露假设，以及你的框架与证据之间的缺口，而不是抹平；
- 分开它找到了什么、记得但未核实什么、推断了什么——并分别标注；
- 当事情真正开放时给出现实选项，而不是假确定或假二分；
- 以适中步伐推进，便于你引导，而不是交付你并未选择的完整框架。

这不是为谨慎而谨慎。它使工具可用于有后果的工作——研究设计、审稿回复、基金申请——在那里「讨好地错」比「慢一点」更糟。

## 思考与动手，在同一条对话里

每条 Alt Theory 对话运行在两种模式之一，并可随工作变化切换：

- **Understand（理解模式）** 面向认真对话、触达有界。智能体在你带入对话的内容与其所知上工作，并诚实标注。
- **Work（工作模式）** 打开实践能力：本机工作文件夹、实时网页与文献搜索、文档阅读与产出，以及越过边界时需你批准的智能体动作。

两者都是智能体式的；区别在于你向智能体开放了多少本机与工具生态。
[理解模式与工作模式](understand-and-work.md) 解释该模型。

## 可读的方法

Alt Theory 的大量行为由**内置技能（bundled skills）**承载——可读的指令文件，编码如何有出处地搜索、如何在大型或含糊工作前与你对齐、如何保留长对话后仍存活的计划记录、如何克制地编辑接近定稿的文本，以及如何组织它创建的文件。它们不是隐藏调参：每个都可打开阅读，你自己的技能可优先于它们。见 [内置技能](../system-guide/bundled-skills.md)。

## 谁适合用

Alt Theory 面向社会科学的学生与研究者——从框定第一个研究问题的硕士生，到判断某工具是否该靠近基金申请的资深研究者。它不预设你有 AI 智能体工具经验。若你已在跑 agent harness，产品建立在 Pi 生态上并能与之协作；见
[应用与插件](app-and-plugins.md)。

## 产品目前在哪

Alt Theory 处于活跃 alpha 开发中。核心应用可用，且已在真实研究中使用；界面与配置仍可能变化，[已知限制](../help/compatibility-formats-limitations.md) 页保持诚实。Alt Theory 也是关于学者究竟需要何种 AI 支持的长期研究项目；若该研究让你感兴趣，见 [版本与进一步帮助](../help/releases-and-further-help.md) 了解如何联系。

# 在研究关键节点上想得更好

研究项目中有些时刻后果格外重大：敲定研究设计、回复审稿人、重构文章、塑造文献综述的论证、判断结果对更大叙事意味着什么、框定一份申请。这些时刻的瓶颈不是产出——是判断。

（与本节其他页相同：这是一类工作，不是一种模式。这些时刻常在 Understand 中展开，需要材料或核实时再伸向 Work。）

## 为何在这里「认真」的工具格外重要

关键节点上，只会附和的助手是负担。若你把审稿回复给只会夸奖的工具看，学不到东西；若你要研究设计却得到一份自信模板，薄弱关节就被藏进了「看起来已完成」的东西里。Alt Theory 在这些时刻的价值是：证据在哪里顶回来，它就在哪里顶回来：

- 事实、时间与归属错误会被直接点名，即便你的总体方向是对的；
- 材料实际支撑的与草稿主张之间的缺口会被摊开，而不是抹平；
- 提出选项时，是带各自依据的现实替代方案——决策仍明显属于你。

## 承载这些时刻的方法

三个内置技能主要为这类工作存在。可从 Toolbox 调用、按名称调用，或直接描述你想要什么：

- **Aligning（对齐）**——在大型或含糊工作开始前，智能体访谈你：分批提问，每题附上它当前最佳猜测，让你看清双方差多远，并在其上搭建之前纠正框架。说「先和我对齐」——或在凭猜测行动成本过高时，它会自己提议对齐。
- **Plan records（计划记录）**——跨对话、跨多日的工作用的活文档：向前规划、向后记录：目标、阶段、每步发现了什么、什么变了。写在这里的决策能在对话压缩后仍存活，可被未来的你、合作者或后续对话阅读。
- **Precise edit（精确编辑）**——面向接近定稿的文本，克制的语言工作：尊重你的结构、语气与有意选择，只标出你未必已知的问题。

## 探索替代路径而不丢掉主线

关键节点通常涉及值得认真对待的替代方案。用 [Branch（分支）](../system-guide/responses-and-controls.md) 展开竞争设计；用 **BTW** 处理不该带偏主讨论的旁线问题；改写较早消息以在不同框架下看讨论如何走。什么都不会丢：原线保持完整，同时你可以在其周围张望。

## 材料不完整、有争议或在变动时

真正的关键节点材料很少干净——半收集的数据集、相互矛盾的审稿意见、改到第三稿的理论部分。正是产品的出处纪律让它仍可用：区分文件实际包含什么与它回忆或推断的什么，说明某次综合实际用了哪些文件，并把「这部分还定不下来」当作合法、可记录的状态，而不是必须填上的空缺。

## 给有经验的研究者

你不必重建任何工作流也能在此获益。这些是时刻，不是流水线：把审稿信、设计备忘、提纲带来——作为文件或粘贴文本——想清楚，带走更锋利的版本，再回到自己的工具。若工具在你工作中赢得更大位置，[以具体动手为主任务时](when-concrete-work-is-the-main-task.md) 展示那会是什么样。

# 以具体动手为主任务时

有时下一步就是干活：查找并核实文献、读 PDF、转换幻灯片、起草章节、修订文档、在项目文件夹里推进。这是 Work 模式的主场——在你的材料上采取智能体行动，并保持与其他一切相同的诚实标准。（与本节其他页相同：这是目标，不是模式——不过这个目标通常需要 Work。）

## 讨论变成行动时会变什么

附加[工作文件夹](../system-guide/working-folders-files-paths.md)后，对话就有了行动场所。此后每一步与聊天工具的实践差异都可见：

- **你看见它在做什么。** 每个动作以一行出现在对话中——读了哪个文件、写了什么、跑了哪条命令、用了哪个技能——需要细节时可展开。
- **你看见改了什么。** 触及文件的一轮会以卡片命名这些文件，并统计增删；新文有预览，改文有前后对照，代码有 diff。
- **边界先问你。** 读取文件夹之外、访问网络、安装任何东西——都会弹出写明请求内容的批准请求。拒绝是安全的。
- **原件仍是你的。** 修订发生在副本或命名清晰的新文件上，智能体会告诉你写到了哪个文件。

## 像真的需要引用一样搜索与引用

文献工作中「编造的自信」伤害最大，因此纪律也最严：

- **学术搜索**使用返回可核验元数据的学术索引——标题、年份、DOI、被引次数。没有真实标识符的文献不会被当成有标识符的交给你。
- **抓取的页面会引用并标明出处**——页面实际说了什么，附上 URL。若公开只有摘要，你得到摘要并被告知就是摘要；抓取不会绕过付费墙，智能体会说明而不是用空话填洞。
- **记忆从不当作搜索。** 回忆而非检索到的内容一律标为未核实。
- **覆盖范围声明是字面意思。**「我读了这五个文件」就是那五个，并列出。综合会点名实际依据了什么。

## 文档进，文档出

研究真正用的格式在这里可用：Word、PDF、Excel、PowerPoint 可阅读与讨论；转换副本与原件并列，带可见的 `_converted` 后缀。产出文档——格式化草稿、表格、幻灯片——始终创建新文件。文档生成若需额外组件，智能体会通过[引导式设置流程](../system-guide/helper-and-guidance.md#guided-setup)提出安装并等你同意。

## 在真实项目文件夹中工作

智能体在写入前会先读懂项目如何组织，并遵循可见约定：产出放在带日期的输出文件夹、计划放在应有位置、不在你根目录乱撒、未经邀请不改名或重组你的东西。长任务可携带[计划记录](think-better-at-key-moments.md)，使已做、已发现、已决定的内容在对话之外仍可存活。

## 行动与理解保持相连

具体工作不断暴露概念问题——编码方案与数据不合、检索中途文献重新框定了你的贡献。这时不必放弃：同一条对话可回到认真讨论，留在 Work 或回到 Understand，实践工作暴露出的一切仍在视野中。这种连续性——思考、证据与执行在同一条线里——正是产品存在的理由。

# 以理解为目标时

有时理解本身不是「真正工作」前的准备——理解就是工作。探索你可能投入一年的方向；弄清两个相近概念究竟在区分什么；在建基于某理论之前审视其假设；发展尚不属于任何单一项目的观点。

进入场景前先说明：本页讲的是*目标*，不是模式。以理解为中心的工作大多自然落在 Understand（理解模式），但也可在 Work（工作模式）中推进——例如需要实时文献检索时。本节三页描述的是工作类型；[模式选择](../start-here/understand-and-work.md)始终由你决定。

## 这类工作在这里是什么样

把未完成的东西原样带来。半成形的问题、相互矛盾的笔记页、你怀疑「承担了过多工作」的某个概念。智能体的职责不是快速收尾，而是帮你看清楚：

- **你的框架会被审视，而不只是被延伸。** 若问题把地方依恋与习惯混在一起，回复会区分二者，并说明每种框架会把你绑到什么承诺上——而不是默默选一个然后在上面搭建。
- **缺口保持可见。** 想法与证据未完全贴合处，会把错位摊开。智能体不会削掉理论棱角好硬套你的案例。
- **不确定性被标注，而不是被填满。** 主张会标明：既有且稳定、合理但未核实、或确实开放。需要实时来源才能核实时，智能体会明确说出来。
- **推进是分步的。** 你得到的是下一处有用的区分或问题，开放处附上现实可选路径——而不是你并未选择的完整框架。

## 如何塑造对话

对以理解为中心的工作，两个杠杆最重要：

- **知识库** 把策展领域材料放进智能体可及范围——当讨论应以此为根基时启用，并请智能体把你的想法连接到其中的具体来源。
- **角色（roles）** 改变呈现方式——更苏格拉底式或更直接，更辅导或更批判。没有角色会改动原则；更温和的语气也不会变成更「讨好」的智能体。

长期理解也值得有意保存。讨论到可暂歇处时，可请智能体做[对话摘要](../system-guide/bundled-skills.md)，或把正在成形的图景写入文件，使它不依赖单条对话存活。

## 核实在流程中的位置

理解型工作常擦到可核对事实——那项研究真的那么说吗？文献现状是否如此？在 Understand 模式中，智能体诚实处理且不做实时检索：它记得的内容会标为未核实（对引用尤其明确），支撑不住的绝不会编造。

当核实成为真正的下一步时，在同一条对话切到 Work：学术搜索返回真实、经 DOI 核验的文献与被引次数，页面可抓取并以来源引用。讨论从原处接上，但已站在经核对的地面上。纪律说明见 [搜索、来源与网页内容](../system-guide/search-sources-web.md)。

## 若你对 AI 的依赖比自己希望的多

学生常高度依赖 AI 建议，也清楚其中心风险：无论对错都显得可信，而导师未必有时间逐条核对。Alt Theory 不能替代指导，但比通用聊天工具更可被审查：

- 请它把支撑每条主张的东西分开——找到的、回忆的、推断的——它会照做。
- 问「什么会让这个框架错了？」它会当真问题处理，而不是趁机安慰你。
- 默认倾向是暴露论证中最弱一环，而不是抛光盖住——包括对自己的建议。

这样用时，工具会成为判断力的练习，而不是腐蚀判断力的替代品。

# 添加与管理技能

## 安装技能

没有应用商店，也没有安装仪式——技能就是可读文件组成的文件夹，安装就是放到应用会查找的位置：

- **给所有工具用**（推荐）：主目录下的跨 harness 技能文件夹
  `~/.agents/skills/<skill-name>/`。此处的技能会被 Alt Theory 与遵循同一约定的其他 harness 发现。
- **在项目内**：工作文件夹中的 `.agents/skills/`（或 `.pi/skills/`）——附加该文件夹时技能生效（Work 模式），并随项目走。

技能文件夹包含描述用途与做法的 `SKILL.md`；可选更多参考文件。格式就这些。你可以用一个下午自己写一个——或请智能体根据你的实践起草，这是真正不错的早期项目。

技能从哪来很重要：技能是智能体会遵循的指令，因此只安装你读过或信任的，就像对待任何准备照做的建议。

## 启用与作用范围

**设置 → 技能** 列出发现的一切——内置、你的、项目的——并控制在哪里加载：

- 启用是**按模式**的：Understand 与 Work 有各自启用集，因为能力边界不同。Understand 在你选择前不从外部技能起步；Work 的默认集更广——两套都可由你改。
- 变更立即保存，但从不静默改写正在运行的对话：新对话自然使用新选择，已打开对话在重新打开时接管。

## 优先级：你的技能与内置技能重叠时

**技能优先级**设置（设置中）是一个全局选择：

- **优先 Alt Theory 内置技能**（默认）——除非你另说，产品方法生效；
- **优先我的技能**——你的同类别技能胜出；
- **问我**——冲突在对话中作为问题出现。

与设置无关，若干内置技能会明确让位于同类别的用户安装技能（文档转换、页面抓取、搜索）——更丰富的领域版本正是用户常带来的。多 harness 组合与细规则见
[共享配置与资产](../advanced/shared-configuration-and-assets.md)。

## 核对

- **本对话哪些技能激活？**「设置 → 技能」显示启用集；对话中技能使用以具名技能行可见——问「你当前有哪些技能？」可得到实时列表。
- **新技能被发现了吗？** 应用重新扫描后出现在「设置 → 技能」（重新打开设置，或首次安装后重启应用）。

## 恢复

- **技能从不触发**：从[命令面板](commands.md)按名称显式调用——显式调用总是有效。
  然后检查其 `SKILL.md` 描述：触发按该描述匹配，描述未覆盖你的措辞就不会触发。
- **错误的技能胜出**：检查优先级设置，以及两技能是否真属同一类别（无关技能不冲突——两者都加载）。
- **项目技能缺失**：确认包含它的文件夹已附加到本对话，且对话在 Work 模式。

# 内置技能

内置技能是写下来的 Alt Theory 方法。每个都是可检查的可读文件；合起来覆盖产品如何查找、如何处理文本与文档、如何运行协作本身，以及如何帮助使用应用。下方每条说明技能为你做什么、使用中如何显现、适用于何处。

你自己的技能可优先于其中任意一个——见
[添加与管理技能](add-and-manage-skills.md)。

## 查找

### search-policy

每次搜索背后的纪律：何时值得实时检索、三方出处规则（此刻找到 / 记忆 / 推断）、对薄弱结果的诚实处理，以及无法核实时的校准回退。你在每条回答的主张与引用标注中看到它。两种模式都适用——在 Understand 中约束无检索时的诚实。

### web-search *(Work)*

实时通用与学术搜索。学术查询走返回 DOI、年份与被引次数的学术索引；通用查询走无需密钥的网页搜索。体现为搜索工具行与你可真正核验的文献。首次使用可能提议安装小工具。

### page-fetch *(Work)*

把 URL 取回为可读文本，以便带来源引用。两档：快速默认；面向反爬期刊站的更重浏览器档（较大安装，首次需要时提供）。不绕过付费墙，并会说明。

## 处理文档与文本

### doc-convert *(Work)*

转换文档（docx、pptx、xlsx、pdf → markdown）供阅读，并按请求生成新文档文件。转换副本与原件并列，带 `_converted`；从不碰你的原件。

### precise-edit

面向接近定稿文本的克制编辑：语言准确而不重构，保留你的有意选择，从不擅自填占位符，选项是真正不同的替代而不是近义词替换。你交出大体完成的文稿时就会显现。

### workspace-conventions

智能体创建文件放哪、如何命名：先读项目自身结构，带日期输出文件夹，计划进 `plans/`，原件不动，不擅自重组。你看到的是：几周智能体工作后工作文件夹仍可理解。

## 运行协作

### adaptive-aligning

方向设定工作的对齐访谈：分批提问，每题携带智能体自己的最佳猜测，让你看清双方差多远；高置信点变成确认而非问题。在你要求对齐时触发（多种措辞与语言），或在凭猜测行动成本过高时触发。

### adaptive-plan-record

跨越多步、超出单条对话的工作用的活计划文档：目标优先，阶段松散持有，每次行动揭示了什么，已决定 vs 假设 vs 仍开放。住在工作文件夹中，因此能在对话压缩后存活，并干净交接给后续对话或合作者。

### conversation-summary

把当前对话变成保存的 markdown 摘要或交接说明——保留出处（你确认了什么、共同发展了什么、什么是智能体推断），开放问题保持开放，不偷偷变成结论。

### imported-session-context

约束[从其他 harness 导入](imports-and-continuity.md)的对话：优先连续性而非猜疑——读当前文件而不是对历史含糊其辞，从不编造导入未携带的内容，从导入自身记录回答「丢了什么」。

## 应用本身

### alt-theory-help

Helper 自身的技能：依据当前文档回答关于 Alt Theory 的问题，使用可见运行时状态，并说明未能核实什么，而不是编造步骤。

### setup-helper *(Work)*

平实语言的环境设置：安装技能所需、提供商与密钥配置指引、可选浏览器档。你体验到的规则就是它的规则——请求前先解释、从不静默安装、事后核实、诚实报告。

### model-image-support

检查特定模型能否读图（对照提供商当前文档，不凭名称猜测），并把答案记入模型配置，使图像附件可用。

# 命令

在输入区键入 `/` 会打开**命令面板（command palette）**——可按名称调用的完整列表，边输入边自说明。

## 里面有什么

- **每个已激活技能**，可调用为 `/skill-name`——立刻应用特定方法的可靠方式，内置或你自己的。
- **对话命令**：
  - `/branch` — 从这里分支本对话；
  - `/btw` — 打开携带当前上下文的旁线对话；
  - `/new` — 开始新对话；
  - `/compact` — 立刻压缩本对话，在你选择的暂歇点，而不是被上限逼迫时。

面板随输入过滤，每条显示做什么——它会教自己，因此 Toolbox 的「所有技能…」入口只是把你丢到这里。

## 命令 vs 句子

面板里的没有一项是唯一做法。「我们在这里分支吧」「开始前先和我对齐」「总结这段对话」作为普通句子也有效——面板存在是为了精确（就是这个技能）、速度，以及发现可用之物。用哪个适合当下就用哪个；智能体把显式命令当指令，不当建议。

# 用聊天机器人配置模型

你可以用任何认真的聊天机器人或编程代理（ChatGPT、Kimi、DeepSeek、Gemini、豆包、Claude、Codex 等）起草 Alt Theory 的模型配置。结果与「设置 → 模型」界面写入的是同一套文件。

## 配置在哪里

- 目录：**`~/.alt-theory/pi-agent/`**（Windows：`%USERPROFILE%\.alt-theory\pi-agent\`）
- **`models.json`** — 提供商、Base URL、模型 id、thinking 级别、上下文窗口等元数据
- **`auth.json`** — API 密钥与 OAuth 令牌（尽量不要把密钥贴进公开聊天）

Alt Theory **不会**读取 `~/.pi/agent/`。格式与 Pi 兼容，可以复制，但路径有意分开。详见 [模型、提供商与访问](models-providers-access.md) 与 [共享配置与资产](../advanced/shared-configuration-and-assets.md)。

## 可复制提示词

把下面提示词复制到聊天机器人，替换方括号内容。若已有 `models.json`，先去掉密钥再粘贴片段。

```text
我使用 Alt Theory（本地研究应用）。模型配置与 Pi 兼容，且只位于 ~/.alt-theory/pi-agent/（不是 ~/.pi/agent/）。

请帮我生成一份可用的 models.json，以便使用 [提供商名称，例如 DeepSeek / OpenRouter / xAI / 本地 OpenAI 兼容服务]。

约束：
1. 除非提供商要求其他 api 类型，否则优先 openai-completions。
2. 使用该提供商当前真实的 model id，不要编造已下线的 id。
3. 在已知时为每个模型填写 contextWindow、maxTokens、reasoning，以及可用的 thinking 级别。
4. 不要把 API 密钥写入 models.json。单独说明密钥应放在哪里（设置 → 模型，或 auth.json 惯例）。
5. 输出完整 models.json，并给出 Windows/macOS 简短步骤：创建目录、保存文件、重开 Alt Theory、打开设置 → 模型、Fetch model list（若可用）、Test connection，然后用页面顶部的「设为默认」（在提供商卡片内点选模型本身不会静默变成默认）。

我的系统是 [Windows / macOS / Linux]。
我的目标是 [例如日常用 Grok，草稿用 DeepSeek]。
现有配置（已去掉密钥）：[粘贴或写 none]。
```

## 拿到答复之后

1. 如无目录则创建 `~/.alt-theory/pi-agent/`。
2. 保存 `models.json`（密钥只放在指引或设置允许的位置）。
3. 重开「设置 → 模型」。
4. 优先 **Fetch model list**，使 id 与提供商当前列表一致。
5. 用顶部的 **设为默认** 指定新对话默认模型。
6. **Test connection** 通过后再做长研究。

## Helper vs 聊天机器人

应用内 **Helper**（Toolbox →「问 Alt 怎么用，或修设置」）可在本机走同一路径。想在打开 Alt 之前先有一份草稿文件，或在远程机器上配置时，用聊天机器人更合适。

# 对话与历史

## 对话列表

左侧面板列出你的对话，按工作文件夹分组，最近活动优先。在列表中你可以：

- **搜索**对话标题。
- **打开**对话以继续。
- 在行菜单中**重命名、删除或复制**对话——无需打开。复制相当于从对话末尾分支：独立副本共享完整历史，之后各走各的。
- 智能体活跃时，一眼看到每条对话的**状态**：运行中、完成但有未读结果、失败，或等待你的批准。

新对话在首次交流后自命名——简短生成标题会替换「首词占位」。重命名权始终在你；手动命名从不会被覆盖。

## 继续与改写

打开对话即完整恢复：历史、模式、工作文件夹、知识库与模型选择均会保留。你也可以重塑主线本身：

- **编辑或改写你较早的一条消息。** 对话从该点起用你的新表述继续；之后轮次从活动线移除。首次操作时应用会先说明这一点。改写用来修正把讨论带偏的框架——比重开对话更省事，也比与题外话纠缠更干净。
- **从任意消息分支**，在相关对话中探索替代路径，原对话保持完整。

各选项保留什么，见 [处理回复与对话控件](responses-and-controls.md)。

## 压缩：长对话如何继续

模型有有限的上下文窗口。对话接近上限时，应用会**压缩（compact）**：较早轮次被浓缩为模型继续携带的摘要，对话继续。

你看到并控制的：

- 压缩是**可见的**：分隔线标记边界，摘要就在那里、可展开——你能读到模型现在实际携带什么。
- 运行时有**状态**，可停止；对话仍可用。
- 可在自然暂歇点用 `/compact` **主动触发**，而不必等到极限。

压缩对工作的含义：摘要忠实但有损。应用自身立场是：关键事实不应只活在转录里——决策应写入[计划记录](bundled-skills.md#adaptive-plan-record)或工作文件夹中的文件，它们从不被压缩。若很久以前陈述的事实很重要，而压缩后的回复似乎丢了它，请重述或指向持有该事实的文件；另见 [搜索、来源与网页内容](search-sources-web.md) 中的诚实规则——智能体被指示应标记而非臆造它已不再拥有的内容。

## 导出与分享对话

把对话拿出去是一等公民操作，两种形式对应两种目的：

- **给人阅读与分享** — [对话摘要或交接说明](bundled-skills.md#conversation-summary)
  为 markdown，或转录的 HTML 导出：导师或合作者无需特殊工具即可阅读。
- **在别处继续** — 对话底层的 Pi 兼容文件，生态中的其他 harness 可拾起并继续。细节：
  [跨 harness 工作](../advanced/cross-harness-work.md)。

## 核对

- **我在哪条对话，附加了什么？** 输入区显示当前工作文件夹、知识库、模型与模式。
- **对话存在哪里？** 列表按工作文件夹分组；对话数据本身存在本地——
  见 [你的数据与隐私](data-and-privacy.md)。

## 恢复

- **一轮被中断**（停止、崩溃、网络）：对话仍可用；已完成动作记在转录中。
  继续，或改写被中断的请求。
- **重新打开后看起来不对**（缺尾、状态异常）：刷新一次；若仍有问题，见
  [故障排除](../help/troubleshooting.md)，并说明对话大致年龄，以及是否导入或压缩过。
- **误删对话？** 列表删除意在移除——请视为最终。若很重要，在本地做其他事之前先联系
  [版本与进一步帮助](../help/releases-and-further-help.md) 中的支持渠道。

# 你的数据、隐私与离开本机的内容

对研究用户而言，这不是偏好页——这是合规问题。敏感访谈、学生记录、受使用协议约束的数据、审稿中的禁运稿：能否使用某工具，取决于能否可辩护地说清数据去哪。本页就是该答案，精确陈述。

## 你的数据在哪里

应用产生的一切都**本地、在这台电脑上**，在一个应用数据目录中：对话及其历史、记录与配置、对话工作区中创建的文件。没有 Alt Theory 云、没有账户服务器、没有遥测管道、没有同步。应用不「打电话回家」。

你自己的项目文件留在原处——附加工作文件夹授予访问权；不会把项目复制或上传到任何地方。

## 究竟什么会离开本机

本地优先**不等于**什么都不离开。存在三股流动，均由你的使用发起：

1. **到你的模型提供商。** 这是必须理解的关键一项：模型响应的一切会发往你配置的提供商——你的消息，以及智能体为工作而读取的文件内容。若智能体读你的访谈转录以回答相关问题，该转录文本就去了提供商，在你的账户与提供商数据条款下。「文件留在本地」对存储成立，对模型看见的内容不成立。敏感工作请据此选择提供商——这与选择把草稿发到哪封邮件是同类判断。
2. **实时检索（Work 模式）。** 搜索发往搜索服务，抓取发往被抓取的站点。查询文本对这些服务可见，就像你在浏览器中做的任何搜索。
3. **没有别的。** 无使用分析、无内容分享、无你在对话工具行中看到智能体使用之外的第三方服务。

(1) 的实践后果：对你不得发给任何第三方的材料，真正要紧的边界是模型提供商。自托管提供商，或条款被你协议允许的提供商，会改变答案；应用本身不增加额外暴露。

## 删除与保留

- 应用对本地对话**无自动保留或过期**——在你删除前它们是你的。
- **删除对话**把它从应用目录移除。对话数据是应用数据目录中的普通本地文件——可审计、可移除；别处不持有。
- **提供商**对已发送内容的保留受其条款约束，不受应用约束——与任何 API 使用相同。

**备份与换机**直接得出：数据目录*就是*应用状态。复制即完整备份；放到新机器上应用会接管。无需导出仪式，无需账户迁移。

## 对伦理委员会怎么说

一段话版本，按字面准确：*该应用将所有对话与工作数据存储在研究者本机本地，除向研究者配置的 AI 模型提供商传输外不外传——提供商接收对话内容以及助手被要求阅读的文件内容——且在使用实时搜索时，将查询文本发往所查询的服务。不涉及第三方分析或存储服务。*

## 核对

- 智能体读了什么（因而提供商看见了什么）：
  [工具行](responses-and-controls.md) 点名每个读过的文件、每次搜索、每次页面抓取——按轮次，在转录中。
- 数据目录在哪：应用的关于/设置界面显示，可像任何本地文件夹一样检查。

# 文档、图像与其他输入

研究材料常以 Word、PDF、表格、幻灯片与图像形式出现。本页是把它们带进来、以及产出文档的权威说明。

## 应用能读什么

工作文件夹中或附加到对话的文件，可按真实格式阅读：

- **Word (.docx)** — 抽取文本供阅读与讨论。
- **PDF** — 文本抽取；尽可能保留页码引用。（纯扫描、仅图像的 PDF 没有可抽文本——这是当前限制，会说明而不是绕过。）
- **Excel (.xlsx)** — 工作表可作为数据阅读。
- **PowerPoint (.pptx)** — 按幻灯片抽取文本。

若需要独立、可检查的转换——或批量处理——智能体可生成文档的 markdown 副本；转换文件出现在**原件旁边**，带 `_converted` 后缀，配对关系可见，原件明显未动。

## 附加 vs 文件夹访问

- **附件**把特定文件放到智能体眼前：拖到输入区、用附加按钮，或从文件面板发送。附件会在你的消息中引用，智能体确切知道你指哪些文件。
- **工作文件夹访问**（Work 模式）让智能体按工作需要自行查找并阅读项目文件——
  [细节](working-folders-files-paths.md)。

## 图像

图像用同样方式附加。*模型*能否看见图像取决于模型：支持图像的模型会收到图像本身；纯文本模型会看到有图像附加并说明读不了——什么都不会坏掉。

应用在你的模型配置中按模型记录图像能力。若你知道模型能读图但应用当纯文本处理，请智能体检查并记录该模型的图像支持——有内置技能专做此事；它对照提供商当前文档核实，而不是凭模型名猜测，并与你一起更新配置。

## 产出文档

要求「以文档形式」输出会在工作文件夹中生成**新文件**，命名清晰，从不覆盖你的任何东西。需要生成组件的格式（写 .docx、.pptx、.xlsx）可能要一次性依赖安装，经[引导式设置](helper-and-guidance.md)提议，且仅在你同意后执行。

当前诚实边界：修订*你的* Word 文档会生成编辑过的**副本**加通俗变更摘要——输出端的 Word 修订痕迹格式尚未支持。见
[已知限制](../help/compatibility-formats-limitations.md)。

## 核对

- 智能体实际读了什么：工具行点名打开的每个文件；综合会点名来源。
- 你的模型是否读图：「设置 → 模型」中该模型条目显示已记录的输入类型。

## 恢复

- **文档读失败**：先确认在原生应用中能否打开；受密码保护与损坏的文件无法抽取。扫描 PDF 见上方限制。
- **图像被忽略**：模型很可能是纯文本——检查已记录能力，或跑上方图像支持检查并重新打开对话。
- **转换看起来不对**（表格乱、格式丢）：转换优先可读文本而非版式保真；版式关键的工作请以原件为准，转换用于讨论。

# Helper 与应用内指引

你正在读的文档是学习应用的一种方式。另一种内置：应用在值得解释的时刻解释自己。

## Helper（帮助助手）

**Helper** 是回答关于 Alt Theory 本身问题的旁线对话——某功能如何工作、设置在哪、为何某行为如此，以及提供商、密钥与工具安装的引导式设置。

两个定义性性质：

- **从干净状态开始。** Helper 不读取你当前对话。这既是尊重隐私的默认，也使它随处可复用——空白界面与项目中途是同一助手。（*应当*携带你上下文的题外话，请用
  [BTW](responses-and-controls.md)；选择时应用会说明这一区别。）
- **依据当前文档作答。** Helper 自身规则要求对任何具体或会变的内容查阅产品当前文档——并说明未能核实什么，而不是凭记忆编步骤。诚实的「我无法确认，请看这里」按设计在其词汇里。

从 Toolbox 打开（「问 Alt 怎么用，或修设置」）。若 Helper 交流对项目变得重要，可提升为分支，变成普通对话。

## 引导式设置

设置任务——缺工具、要配置的提供商、期刊访问的可选浏览器档——经
[setup-helper 技能](bundled-skills.md#setup-helper) 用平实语言运行：
将安装什么、让你能做什么、有多大，然后你的 yes/no，再核实是否真的生效。从不静默安装；拒绝安装时，若有无安装替代方案会给你。

模式说明：*解释*设置随处可用——Helper 在任何对话中回答配置问题。*执行*安装是行动，因此在具备 Work 能力的对话中运行；若从 Understand 询问，会被指向切换，而不是卡住。

## 在正确时刻教

应用避开入门的两个极端——没人读的导览，与没人找到的功能：

- **一次性说明**在你首次使用会改写历史的动作时出现（改写消息、首次分支）——短通知，一次。
- **轮换提示**在你已在等待时（思考或长工具运行中）露出一行能力——零成本、不打断。
- **命令面板自我教学** — 键入 `/` 就是应用自己的索引。

## Helper 不够时

Helper 了解产品；它不了解你的缺陷。问题见
[故障排除](../help/troubleshooting.md)；限制见
[已知限制](../help/compatibility-formats-limitations.md)；找人见
[版本与进一步帮助](../help/releases-and-further-help.md)。

# 技能如何工作

**技能（skill）** 是可读的指令文件，塑造智能体如何处理某类任务——何时搜索、如何引用，如何编辑接近定稿的文本，如何组织它创建的文件。技能是 Alt Theory 方法的打包方式：透明、可检查、可替换。

## 为何用技能，而不是隐藏调参

技能做的一切都写在技能文件里，用平实语言。你可以打开任意技能，读到智能体究竟被吩咐了什么。由此有三个值得在意的后果：

- 你可以**审计**你注意到的行为背后的方法；
- 你可以**添加**自己的技能，并以平等身份参与；
- 技能遵循生态惯例，因此可以**迁移**——更广智能体生态的技能在这里可用，Alt Theory 的技能也可在其他 harness 中用。

## 技能从哪来

三个来源，都在设置中可见：

- **内置（Bundled）** — 随产品发布；承载其方法
  （[目录](bundled-skills.md)）。
- **你安装的** — 放在本机标准技能文件夹
  （[如何](add-and-manage-skills.md)）。
- **项目技能** — 住在你附加的工作文件夹内；随项目来去（Work 模式）。

## 技能如何激活

两条路径：

- **按匹配。** 每个技能声明自己用途。当你的请求匹配时，智能体加载并遵循该技能。这是判断，不是关键词魔法——按含义匹配描述。
- **显式。** 从[命令面板](commands.md)按名称调用任意技能，或通过其
  [Toolbox](toolbox.md) 入口。当你要应用特定方法时，显式调用是可靠路径。

加载技能是**可见的**：回复中有一行点名所用技能——不会伪装成普通读文件。若你预期技能会触发却没有，按名称调用总是有效；发现漏触发值得
[报告](../help/releases-and-further-help.md)。

## 技能与模式

仅作指令的技能（如何对齐、如何编辑）两种模式都可用。方法需要工具的技能——实时搜索、页面抓取、文档转换——是 **Work 专用**，因为 Understand 刻意没有命令执行。[模式页](../start-here/understand-and-work.md)
说明边界；每个内置技能条目会写明它在哪一侧。

## 技能重叠时

你可能安装与内置技能覆盖同一领域的技能——更丰富的文档技能、你学科的搜索实践。谁优先由你设定：**优先级设置**可选 prefer-bundled（优先内置）、prefer-yours（优先你的）、或 ask-each-time（每次询问）；若干内置技能还会按自身文本让位于同类别的用户安装技能。权威细节：[添加与管理技能](add-and-manage-skills.md)；
进阶组合策略：
[共享配置与资产](../advanced/shared-configuration-and-assets.md)。

# 导入、交接与跨 harness 连续性

你在其他 AI 工具中已做的工作不必留在那里。Alt Theory 可从其他 agent harness 导入对话并作为自己的继续——离开时也可向外交接。

## 导入对话

支持的来源：**Claude Code、Codex、OpenCode、Grok Build**。
（Pi 格式会话是 Alt Theory 自身原生格式，可直接带入——见 [跨 harness 工作](../advanced/cross-harness-work.md)。）
导入入口出现在产品该出现的地方：创建对话时的空状态，以及导航菜单。

流程：

1. **发现** — 应用在本机找到源工具的对话并列出，可搜索，最近优先。
2. **预览** — 在创建任何东西前，完整检查所选对话，并展示导入将携带什么。
3. **导入** — 对话变成普通 Alt Theory 对话：可读历史、可继续，列表名标明来源。

源工具中任何东西都不会被修改。导入只读，从不回写。

## 什么忠实导入——什么不装假

导入的对话是忠实但诚实的投影：

- **携带**：你的消息与助手消息、工具活动、可恢复时的图像与附件，以及源以可读方式存储时对话自身的压缩摘要。
- **标注，不伪造**：源记录了但导入无法重放的内容（不可导出的附件、提供商私有状态）以标注占位符出现，写明那里曾是什么。完整源记录作为可搜索证据与对话并置保存。
- **拒绝，不编造**：导入器无法如实表示的源对话——历史含糊、无法识别的内容——会说明理由拒绝。从不做看似合理的重构。

给定导入转换了什么的完整列表与对话一起存储，智能体从该记录回答「导入丢了什么？」，而不是猜。

## 继续导入的对话

第一轮表现会像你希望同事那样：接上线。智能体把导入上下文当可用上下文——且因世界可能在导入后变动，它在真正动手时的第一步是**读你当前文件**，再就看起来已变动的具体事项发问（计划步骤已完成、文件日期晚于导入），而不是用免责声明或「告诉我改了什么」迎接你。

对之后又有变化的源对话重新导入会创建**新副本**——从不合并进或覆盖你已有的 Alt Theory 续写。

## 向外交接

连续性双向：

- **对话摘要与交接说明** — 索取一份
  （[内置技能](bundled-skills.md#conversation-summary)）；落地为出处处理顺的 markdown 文件，合作者、导师或其他工具可读。
- **Pi 兼容会话** — 对话以 Pi 格式存储；可在 Pi 中继续再回来。深入说明：
  [跨 harness 工作](../advanced/cross-harness-work.md)。

## 核对 / 恢复

- **这次导入携带了什么？** 问智能体，或查对话的导入记录——两者来自同一份存储列表。
- **我的对话未出现在导入列表**：源工具的数据须在本机；检查来源是否支持（上表），并见 [故障排除](../help/troubleshooting.md) 的分源说明。
- **导入被拒绝**：显示的理由是真实原因——通常源自身记录在某处不完整或含糊。导入器不能猜；源对话仍完整留在原处。

# 知识库与上下文

**知识库（knowledge base，KB）** 是智能体在对话中可查阅的策展参考材料——事先选定并组织的领域来源集合，有别于任一项目的工作文件。

## 知识库 vs 工作文件夹

两者容易混，值得分开：

- **工作文件夹**是*你的项目*：你当前正在做的文件，附加后智能体可在那里行动。
- **知识库**是*参考*：智能体可用来奠基讨论的稳定材料——像书桌与身后书架的差别。

一条对话可以两者都有、只有其一，或都没有。

## 启用与关闭

输入区旁的 KB 选择器为本对话选择知识库。应用随附领域知识库（当前目录显示已安装内容——环境心理学核心是第一批）；你也可以添加自己的
（[定制](../advanced/customization-without-changing.md)）。

选 **none（无）** 表示没有可查阅的知识库——其他不变；工作文件夹与附件不受影响。可在对话中途更改 KB 选择；从下一轮起生效。

## 智能体实际如何用 KB

这里需要诚实预期。启用 KB 不会每轮强制查阅，也不会把智能体变成对这些文件的搜索引擎。实际发生的是：智能体知道知识库可用及其覆盖范围，在讨论需要奠基时按判断查阅——就像它决定是否读项目文件。你也可以明确指挥：「对照 KB 检查这个」「知识库对 X 怎么说」——当具体来源很重要时，显式请求是可靠路径。

## 核对

- **KB 是否激活？** KB 选择器一眼显示当前选择。
- **是否真正用到？** 查阅会作为工具行（KB 内的读取）出现在回复中。若要对某条主张求确证，直接问：「那是来自知识库吗，哪个文件？」——出处纪律对 KB 材料与对其他一切同样适用。

## 恢复

- **回答无视 KB**：显式请求（见上）；检查 KB 选择器是否真有选择而非 none；并考虑问题是否真正触及 KB 领域——智能体不会硬塞无关材料。
- **对话中途换了 KB 且内容显得过时**：变更作用于新轮次；较早回答奠基于当时激活的 KB。把要紧的问题再问一遍。

# 模型、提供商与访问

Alt Theory 提供环境、方法与界面；AI 模型来自你配置的**提供商（provider）**。本页是该链路的权威说明。

## 模型芯片

输入区旁的模型芯片显示本对话使用的模型（以及已设置时的 thinking 级别）。悬停可看提供商与用量细节。点击可为当前对话切换模型——从下一轮起生效，对话不中断。

## Thinking 级别、上下文窗口与模型元数据

不同提供商宣告不同能力。Alt Theory 在每个模型条目上存储这些事实（经「设置 → 模型」，或写在 `models.json`）：

- **Thinking / reasoning 级别** — 输入区可提供的努力选项（例如 off / low / medium / high）。只有你启用的级别会出现在芯片中。若模型不推理，芯片会省略努力级别。
- **上下文窗口** — 对话大致 token 预算。提供商回报用量时，输入区旁的上下文环会用到它。
- **最大输出 token** — 模型条目有记录时，单条回复的软上限。
- **图像输入** — 模型是否在轮次中接受图像。

**Fetch model list**（提供商编辑器中、模型列表上方）是从提供商刷新 id 与能力标志的首选方式。提供商不暴露列表时（部分预设），请手工输入模型 id 并校正元数据，使输入区与上下文环保持诚实。

**新**对话的默认模型用「设置 → 模型」顶部的 **设为默认（Set as default）** 指定——在提供商编辑器内点选模型本身不会改变默认。（若尚无默认，保存第一个提供商时会把其第一个模型设为默认。）

## 设置提供商

配置在 **设置 → 模型**，同一界面也用作首次运行设置。支持两类访问：

- **API 密钥** — 来自 DeepSeek、Anthropic、OpenAI 或任何兼容端点。把密钥粘贴到提供商设置项；密钥本地保存在应用配置中，保存后不会再显示回来。
- **订阅登录** — 支持的提供商（目前 OpenRouter、xAI、OpenAI Codex）可通过各自登录流程连接，而不用密钥。

在至少一个提供商有效且激活之前，对话无法开始——应用会清楚拒绝，而不是在中途奇怪失败。你可以配置多个提供商与模型，并按对话选择。

若这些不熟悉，不必独自摸索：
[Helper](helper-and-guidance.md) 会用平实语言带你走完提供商设置——密钥从哪拿、放哪、如何确认可用。密钥属于设置，不属于聊天消息；若你粘贴进对话，智能体会帮你挪到正确位置，并建议不要在聊天中分享密钥。

更想先用通用聊天机器人起草文件？见
[用聊天机器人配置模型](configure-models-with-chatbot.md)。

### 配置实际在哪里

日常使用不必碰这些路径，但它们是设置界面背后的真相；若你已在跑 Pi，就更重要：

- 本地应用把模型配置放在 **`~/.alt-theory/pi-agent/`**
  （Windows 为 `%USERPROFILE%\.alt-theory\pi-agent`）：`models.json` 管提供商与模型，`auth.json` 管密钥与登录令牌。
- 它**不读取 `~/.pi/agent/`**。Alt Theory 不继承、不共享、不同步 Pi 安装的提供商配置——这种分离是有意的（[归属](../advanced/shared-configuration-and-assets.md#ownership)）。
- 文件在*格式*上与 Pi 兼容，因此两者之间搬配置是复制，不是转换。

**从 Pi 过来且那边提供商已可用**：要么在「设置 → 模型」再加一遍（一分钟，也最安全），要么请 Helper 对话协助迁移——它会与你一起查看现有配置，可见地复制有用部分，不碰 Pi 侧。
[共享配置与资产](../advanced/shared-configuration-and-assets.md)
是共享与否的完整说明。

## 费用与用量

模型使用由你的提供商按你的账户与其定价计费——应用不加价。为让用量可见，输入区旁的上下文环（见 [回复与控件](responses-and-controls.md)）显示对话的上下文占用，工具提示含 token 计数与提供商回报的累计费用。若担心意外费用：费用只在智能体实际回复或工作时累积；长时间无人值守任务正是值得瞥一眼可见费用数字的时候。

## 切换模型，以及什么会保留

- **对话中途切换**：随时允许；历史带过去。不同模型各有所长——把难的一轮换到更强模型是正常用法。
- **模型消失**（从你配置中移除，或提供商下线）：重新打开此类对话不会失败。应用回退到默认模型并可见说明；原选择会被记住，若模型回来，对话会重新拿到它。
- **图像能力**：模型是否接受图像记在模型配置中；见
  [文档、图像与其他输入](documents-images-inputs.md)。

## 核对

- 哪个模型在用：模型芯片，始终当前。
- 提供商是否工作：「设置 → 模型」显示各提供商状态；快速测试是发一轮一行的对话。

## 恢复：「我配了，但不工作」

按此列表往下查；多数情况能解决：

1. **提供商是否已保存且激活？** 草稿条目（未带有效密钥就保存）会存着但不可用。
2. **密钥是否有效且有余额？** 在提供商自己的控制台测试；过期试用与未充值账户是最常见原因。
3. **模型 id 是否仍有效？** 提供商会下线模型版本；查提供商的模型列表，不要猜。
4. **重启对话。** 配置变更作用于新建与重新打开的对话，不会在中途静默生效。
5. 仍卡住：[Helper](helper-and-guidance.md) 可与你一起检查配置状态，或见
   [故障排除](../help/troubleshooting.md)。

# 权限、批准与智能体活动

本页是 Alt Theory 信任模型的权威描述：智能体可以做什么、什么总是先问、你如何看到正在发生的事，以及你的选择意味着什么。

## 用平实语言说模型

你分层决定一条对话有多大触达：

1. **Understand 模式** — 无命令执行、无实时网络、无项目文件夹。对话、你的附件与所选知识库是全部表面。越界读取会弹出批准请求。
2. **Work 模式，在已附加文件夹内** — 智能体无需逐轮询问：读项目文件、写新文件、运行其技能描述的命令。这是你通过附加文件夹设定的边界；在边界内，顺畅推进是重点。
3. **Work 模式，在边界上** — 有些事无论触及哪个文件夹都会询问：
   - 读取你未附加的文件或文件夹；
   - 超出内置搜索与抓取工具的网络访问；
   - 安装任何东西；
   - 安全策略标记的操作（危险命令模式、逃出工作区的路径、可疑网络目标）。

## 批准请求

当某事越过边界时，对话暂停并显示：**操作**（究竟要尝试什么）与**范围**（说 yes 授予什么）。你的选项至少包括允许一次与拒绝；在底层策略支持时，会明确提供更广范围（本对话剩余时间）——从不默认假定。

两个值得信任的性质：

- **拒绝是安全的。** 智能体吸收拒绝并继续——另找路径，或坦率告诉你没有该访问时做不到什么。拒绝从不会损坏对话。
- **无答复等于否。** 若请求超时或对话关闭，结果视为拒绝。沉默从不成为同意。

## 诚实界定这是什么

这些是同意与护栏，不是物理隔离：策略层按规则检查操作，批准在边界把你纳入回路——与其他生产级智能体工具姿态相同。它不是操作系统沙箱，文档也不会那样称呼。两个后果：

- 保护为**监督诚实智能体做真实工作**而设计，不是为遏制主动恶意软件。
- 你安装的扩展与工具以你的用户权限运行——当作**受信任软件**：只安装你信任的、来自你信任的来源，就像任何程序。（技能是指令而非代码，但同样适用「只装你信任的」。）

## 看见智能体在做什么

可见性是持续的，不只在边界：

- **在对话中**：每个动作发生时都是
  [工具行](responses-and-controls.md)——读、写、命令、搜索、技能使用——可展开看细节。改动了文件的一轮以变更文件卡片结束。
- **跨对话**：对话列表标记每行实时状态——运行中、完成未读、失败，或**等待批准**——全局指示器显示多少对话在活动。若应用窗口在后台，完成、失败或阻塞在批准上会发系统通知，对话不会整个下午静默等你。

## 核对

- 智能体此刻在做什么？状态区显示当前阶段；工具行实时累积。
- 它实际改了什么？轮次结束卡片与文件面板的变更视图，按轮次与按文件。
- 什么在等我？列表状态与全局指示器。

## 恢复

- **拒绝了某事而工作卡住**：说明你更希望它怎么做——拒绝是转向，不是死胡同。若访问确实需要，附加文件夹或在再次请求时批准。
- **批准了后悔的事**：允许一次用过即消耗；对话范围的批准随对话结束。说清楚，智能体不会重复该操作。
- **动作中途被打断**（停止、崩溃）：已完成步骤记在转录中；没有部分隐藏。问「那到哪了？」并从诚实答案继续。

# 处理回复与对话控件

本页是阅读智能体向你展示的内容、以及引导对话的权威说明。

## 阅读回复

回复可以不只是文字：

- **Thinking（思考）** — 模型作答前的推理，以可折叠块显示。读它是可选的；存在是因为*如何*得出结论往往与结论同样有用。
- **工具行（tool lines）** — 每个智能体动作一行轻量记录，按类型表述：读文件、写文件（带文件名）、编辑文件、跑命令（命令本身在行上）、搜索，或使用具名技能。点击可展开发生了什么：新文有短预览，改文有前后对照，代码有 diff，命令有输出。
- **渲染内容** — markdown 表格渲染为表格；mermaid 图示渲染为图。
- **轮次结束的变更文件卡片** — 当一轮改动了文件，卡片列出它们并显示增删。点进文件面板看完整细节。（导入的对话在导入轮次没有动作日志，因此不显示卡片——应用不会伪造一张。）

## 上下文环

输入区旁有一个小环，显示本对话已用模型上下文窗口的多少。工具提示分解输入/输出 token、缓存使用，以及提供商回报的费用。环接近满时，[压缩](conversations-and-history.md) 是对话继续的方式。

## 引导控件

- **Stop（停止）** — 中途中断智能体。随时安全；已做的会记下来，你从那里引导。
- **Copy（复制）** — 任意消息，你的或智能体的。
- **Edit / revise（编辑 / 改写）** — 改你较早的一条消息；对话从该点起用新表述继续，之后轮次离开活动线（[细节](conversations-and-history.md)）。
- **Branch（分支）** — 从任意消息开始相关对话。分支携带到该点为止的一切；原线不受影响。
- **BTW** — 右侧小栏中的旁线对话，携带当前上下文，处理不该弄乱主线的题外话。长大了的 BTW 可**提升为分支**。
- **Helper** — 也在对话旁，但*从干净状态开始*，看不到你的讨论；用于关于应用本身的问题（[细节](helper-and-guidance.md)）。在你选择二者时，应用会说明这一区别。

## 我想用哪个？

| 你想… | 使用 | 保留什么 |
|---|---|---|
| 修正带偏讨论的框架 | 改写 | 到改写消息为止的历史 |
| 对已完成对话试不同续写 | 复制（从列表） | 完整历史的独立副本 |
| 认真对待替代路径 | 分支 | 到分支点为止的一切，新线 |
| 问题外问题 | BTW | 完整当前上下文，侧栏 |
| 问应用怎么用 | Helper | 不带入任何东西——设计上干净上下文 |
| 开真正新话题 | 新对话 | 什么都没有——干净起点 |

## 恢复

- **停了回复又后悔**：直接请智能体继续——什么都没丢。
- **改写了错误的消息**：移除的轮次已从活动线消失；若重要，下次先从改写前分支。拿不准时先分支，再改写。
- **表格或图示渲染不对**：源文本完好——可复制出去；渲染问题是外观问题，值得
  [报告](../help/releases-and-further-help.md)。

# 搜索、来源与网页内容

Alt Theory 中存在实时检索只有一个理由：让智能体关于世界的说法能对照世界来核对。本页说明有哪些检索、背后的出处纪律，以及没有检索时会发生什么。

## 有哪些检索（Work 模式）

- **学术搜索** — 直接查询学术索引（OpenAlex 与 Crossref），返回可核验元数据：标题、年份、DOI、被引次数与摘要。无需账户或密钥。这是文献工作的首选，因为带 DOI 的结果是你真能交给同事的文献。
- **通用网页搜索** — 其他一切：时事、软件文档、机构页面。同样无需密钥。
- **页面抓取** — 把特定页面取回为可读文本，以便带来源引用主张。两档：快速默认，以及面向反爬期刊站的更重浏览器档（首次需要时通过[引导式设置](helper-and-guidance.md)提供的单独、较大安装）。

Toolbox 的「在线查找」会调用这些；直接提问也可以。需要安装的搜索工具会通过批准流程提议一次。

## 出处规则

智能体交给你的每条事实陈述恰好属于三类之一，且必须保持区分：

- **此刻找到的** — 本对话中工具返回的。附带链接或 DOI。
- **模型记忆** — 回忆但未在此刻核实。标为未核实（引用尤其明确，例如「[Author, year?] — unverified」），或暂不给出。
- **推断** — 由其他事物推理得出。会用文字说清楚。

记忆从不当成搜索结果出场。这一条规则几乎就是产品文献工作可信的大部分原因。（关于规则本身的诚实说明：它通过产品指令与方法执行，在测试中表现良好——但没有任何系统能使编造不可能。若你发现未标注的主张，那是值得[报告](../help/releases-and-further-help.md)的缺陷，不是吹毛求疵。）

实践中你会注意到的两个推论：

- **样本量诚实。** 少数结果是有偏样本：一条摘要只支撑「有来源这样说」，绝不支撑「学界一致认为」。结果冲突时你看到的是分布，不是静默挑一个。
- **覆盖范围诚实。** 综合会点名实际读过哪些来源。「读完 40 个 PDF」就是 40，否则不说。

## 付费墙与访问限制

抓取不会绕过付费墙。若页面对公众只显示摘要，智能体就只得到摘要——并会说「仅摘要」并在其范围内工作，而不是填洞。期刊站的反爬墙常可用受保护抓取档通过；真正的付费墙不行，假装能过正是本产品要避免的那种编造。

## Understand 模式：无实时检索，诚实处理

Understand 按设计没有实时检索——收窄触达正是该模式的意义。对可核对事实，智能体默认是校准过的诚实：给出按扎实程度标注的当前最佳理解（既有 / 合理但未核实 / 未知），标出需要核实之处，绝不编造无法核对的引用。当核实成为任务时，把对话切到 Work——Understand 中 Toolbox 的查找入口会直接说明这一点，而不是显示禁用按钮。

## 核对

- 主张是找到的还是回忆的：会有标注；若偶有缺标，问——「这是此刻找到的还是来自记忆？」是正常问题，且要求诚实回答。
- 搜索实际做了什么：工具行显示每次查询与抓取。

## 恢复

- **搜索没什么用**：试另一条线（学术 vs 通用）、改写问题，或抓取已知可靠的起点页并顺其参考文献。模糊问题可先做廉价部分搜索——搜索与问题会彼此收紧。
- **抓取失败或返回挑战页**：诊断如此时智能体会升到受保护档；若该档未安装，会提议安装而不是静默失败。
- **需要的工具未安装**：引导式设置流程在对话中处理，需你确认。

# 设置与配置

## 设置地图

**设置**收集应用级配置。按对话的选择——模式、模型、角色、知识库、工作文件夹——在对话本身，不在这里。

- **通用** — 界面语言（目前英语；中文计划中）、thinking 块显示等偏好。
- **模型** — 提供商、密钥与登录、模型条目及其能力。权威页：
  [模型、提供商与访问](models-providers-access.md)。
- **角色与知识库** — 可用角色预设与知识库，以及新对话默认值。

  **角色（role）** 是智能体的可选呈现层——语气、节奏、苏格拉底式还是直接——从角色选择器按对话选择（或不选 None，完全合理的默认）。角色改变智能体听起来如何，从不改变原则：身份层（**soul**）明确高于任何角色，因此更温和的语气不会变成更讨好的智能体。添加自己的角色：
  [定制](../advanced/customization-without-changing.md)。
- **技能** — 发现的一切、按模式启用，以及优先级设置。权威页：
  [添加与管理技能](add-and-manage-skills.md)。
- **自动标题** — 对话是否自命名，以及可选由哪个模型命名。

## 变更何时生效

处处一条规则：设置变更**立即保存**，但从不静默改写正在运行的对话。新对话自然接管；已打开对话在重新打开时接管。若变更不重启无法应用，应用会在变更当下说明。

## 谁拥有哪份配置

Alt Theory 处于生态中，因此值得精确说明谁配置什么：

- **应用拥有自己的模型、提供商与技能启用配置**，存在自己的本地目录。它不会持续镜像其他工具的配置；指向外来配置主目录也不是共享方式。
- **从生态中它*读取***：标准跨 harness 位置的技能，以及已附加工作文件夹中的项目资源。读取是发现，不是同步——源留在原处，归放置者所有。
- **工作文件夹贡献**其自身项目上下文与技能给附加到它的对话，仅在附加期间。
- **若你已用 Pi 或其他 harness**：现有设置可*迁移*——Helper 可与你一起检查现有配置，一次、可见地带来有用部分——而不是同步。跨这一切的优先级与组合规则：
  [共享配置与资产](../advanced/shared-configuration-and-assets.md)。

## 磁盘上在哪里

所有应用数据——配置、对话、记录——存在本机一个本地应用目录
（[是什么与在哪](data-and-privacy.md)）。进阶用户想要的两个事实：模型/提供商配置以 Pi 兼容文件存储；每条对话保留创建时所用资产与配置的精确记录，使设置变更后过去对话仍可解释。检查该记录：
[兼容性、更新与集成调试](../advanced/compatibility-updates-debugging.md)。

# Toolbox（工具箱）

Toolbox 是输入区旁的小菜单——通向应用重点动作的前门。它刻意很短：少数几个入口，覆盖除打字之外最常见的需求。

## 入口

- **问 Alt 怎么用，或修设置** — 打开
  [Helper](helper-and-guidance.md)，面向关于应用本身问题（及引导式设置）的干净上下文旁线对话。
- **对齐计划或决策** — 调用
  [对齐技能](bundled-skills.md#adaptive-aligning)：智能体访谈你，在方向设定工作前建立共识。
- **计划与记录** — 调用
  [计划记录技能](bundled-skills.md#adaptive-plan-record)，用于值得跨对话跟踪的工作。
- **在线查找** *(Work)* — 调用
  [实时搜索](search-sources-web.md)。在 Understand 模式此入口不是变灰的按钮：而是一句话，说明 Understand 没有实时检索，切到 Work 才是搜索方式。
- **所有技能…** — 进入[命令面板](commands.md)，`/` 已预填，一切可调用之物都在那里。

## Toolbox 不是什么

它不是技能系统——只是策展过的前门。每个 Toolbox 入口都有长写等价物（命令，或普通句子），这里未突出的一切距离 `/` 只有一步。若你不再需要前门，什么都不会丢。

# 工作文件夹、文件与路径

**工作文件夹（working folder）** 是 Work 模式对话所附加的本机文件夹。智能体的实践工作发生在这里：阅读你项目的文件，并创建新文件。

## 附加工作文件夹

创建 Work 对话时选择工作文件夹，或之后再附加。选择使用系统常规文件夹对话框。对话列表按工作文件夹分组，久而久之列表会镜像你的项目结构。

也可向同一对话**再添加更多文件夹**——例如工作横跨一个项目与一份资料集合。添加文件夹是有实际含义的有意动作：智能体获得访问权，也会读取该文件夹自身的约定（给 AI 智能体的说明、项目结构），以便按该项目期望的方式工作。

没有工作文件夹时，Work 对话仍有私有草稿空间供它创建文件——但看不到你的项目。

## 智能体在哪里能做什么

- **在已附加文件夹内**：按工作需要读文件、创建或编辑文件，无需每一步打断你。它所做的一切会在对话中实时可见。
- **在已附加文件夹外**：读取你未附加的文件或文件夹会触发[批准请求](permissions-approvals-agent-activity.md)——你看到路径再决定。在已附加文件夹外写入根本不可用——工作文件夹是修改的硬边界；批准覆盖读取、网络与安装。
- **在 Understand 模式**：项目文件夹未附加。Understand 对话保留私有对话工作区，智能体可在其中保存你要求的东西——对话摘要、笔记——但你的文件只作为附件进入，越界读取走批准。

## 智能体如何对待你的项目

智能体在你文件夹中遵循的约定本身可读——它们是[内置技能](bundled-skills.md)的一部分：

- **先读。** 写入前先弄清项目如何组织，并优先遵循你的既有结构而非自己的默认。
- **原件不动。** 修订你的文档意味着写副本或命名清晰的新文件——从不原地改你的文件。
- **产出可找到。** 它创建的东西放到合理位置——产出物进带日期的输出文件夹，计划记录进 `plans/`——不在根目录乱撒。
- **不擅自重组。** 它从不会自行改名、移动或重组你的文件；它建议，你决定。

## 文件面板

对话右侧面板以文件树显示工作文件夹：浏览、打开查看，或在 Finder/资源管理器中显示。可从这里把文件带入讨论；智能体工作后也可在此检查改动——见
[处理回复与对话控件](responses-and-controls.md)。

## 路径

智能体提及文件时路径清晰，尽可能相对工作文件夹。文档转换副本与原件并列，带 `_converted` 后缀
（[细节](documents-images-inputs.md)）。

## 核对

- 附加了哪些文件夹：对话配置区与文件面板可见。
- 本轮智能体实际读了什么：对话中的工具行点名打开的每个文件。

## 恢复

- **对话上次运行后文件夹被移动或改名**：重新打开不会静默指向死路径。应用会告知文件夹缺失，并提供重新选择或在没有文件夹的情况下继续——对话与历史不受影响。
- **「为什么看不见我的文件？」** 按序检查：文件是否在已附加文件夹内（而不是磁盘任意处）？对话是否在 Work 模式？文件是否在智能体上次列出文件夹之后才创建（请它再看一次）？若文件在文件夹外，附加其所在文件夹，或预期读取会弹出批准。
- **智能体写的文件找不到**：该轮的变更文件卡片与工具行会点名每个写入文件及路径——先查那里再搜磁盘。

# 兼容性、格式与已知限制

参考表，保持诚实。列为限制的是当前边界，便于你据此规划——不是何时会变的承诺。

## 平台

| 平台 | 状态 |
|---|---|
| macOS（Apple Silicon） | 支持（打包应用与源码构建） |
| Windows（x86） | 支持（打包应用与源码构建） |
| 其他组合（Intel Mac、Windows ARM、Linux） | 未测试、不作承诺；源码构建可能可用但未核实 |

## 界面语言

| 语言 | 状态 |
|---|---|
| 英语 | 当前 |
| 中文（简体与繁体） | 计划中 |

对话语言依赖模型，实际上不受限——智能体用你使用的语言回答。

## 文件格式

| 格式 | 读 | 产出 |
|---|---|---|
| Markdown / 纯文本 | 是 | 是 |
| Word (.docx) | 是 | 是（作为新文件；需一次性组件安装） |
| PDF | 文本抽取（无 OCR——扫描/仅图像 PDF 抽不出） | 否 |
| Excel (.xlsx) | 是 | 是（作为新文件；组件安装） |
| PowerPoint (.pptx) | 是（按幻灯片文本） | 是（作为新文件；组件安装） |
| 图像（PNG、JPEG、GIF、WebP） | 在支持图像的模型上 | 对话中 mermaid 图示 |

## 导入来源

| 来源 | 状态 |
|---|---|
| Claude Code | 支持 |
| Codex | 支持（加密推理/摘要保持不重放，已标注） |
| OpenCode | 支持 |
| Grok Build | 支持 |
| Pi | 原生格式——直接可续写，而非经导入对话框 |
| 其他工具 | 不支持；从源工具导出 markdown 是手动路径 |

导入仅限本地（源工具数据须在本机），对源只读。边界细节：
[导入](../system-guide/imports-and-continuity.md)。

## 提供商访问

API 密钥适用于任何已配置的兼容提供商。订阅登录对支持的提供商可用（目前 OpenRouter、xAI、OpenAI Codex、Anthropic）。兼容 API 的本地模型服务器可配置为提供商。

## 已知限制

- **无 Word 修订痕迹输出。** 修订你的 .docx 会生成编辑副本加通俗变更摘要——不是 Word 修订标记。
- **无 OCR。** 纯扫描/仅图像 PDF 没有可抽取文本。
- **无云文档集成。** Google Docs、Overleaf 等除手动导出/导入文件外不可达。
- **Understand 模式无实时检索** — 设计如此，代之以诚实标注（[原因](../system-guide/search-sources-web.md)）。
- **不绕过付费墙。** 付费源你得到的是公开摘要。
- **无文献管理器集成。** 文档中的 Zotero/EndNote 域代码在你原件中原样保留（原件从不被编辑），但应用不读写文献管理器数据。
- **一个窗口焦点一条对话** — 并行 Work 对话会运行并信号状态，但只有一个活动视图；重型多智能体编排不是本产品。
- **alpha 仍在动。** 界面与内置资产发布间仍可能变化；[策略](../advanced/compatibility-updates-debugging.md)
  精确说明什么受保护、什么不受。

# 常见问题

跨页或触及产品边界的问题。功能问题会指向权威页，而不是在此重复作答。

## 关于使用

**它能帮我写论文吗？**
它可以与你一起起草、修订、重构文本，并在过程中对来源诚实。它不会交给你一份藏起思考的抛光成品——按设计它会暴露缺口、替代路径与不确定性，留给你判断。若你想要的是每条提示最大化「听起来已完成」输出的工具，本产品刻意不是那种。你得到的是可辩护的工作。

**为什么它不直接给我答案？**
问题真正已有定论时，它会直白回答。当它放慢——区分概念、问什么证据会改变你的主张、给出选项——那是产品在工作：对研究问题，过早的自信答案通常是错的。若你希望它表态，直说；它会表态，同时告诉你该表态立在什么之上。

**使用需要懂技术吗？**
不需要。应用一次安装，设置用平实语言引导
（[Helper](../system-guide/helper-and-guidance.md)），不预设终端经验。唯一可辨认的技术步骤——从模型提供商拿到 API 密钥——会逐步引导。

**该用哪个模型？**
应用与模型无关；质量跟随模型，因此判断重的工作用预算允许的最强模型。产品的方法（出处标注、诚实的不确定性）跨模型成立——由产品自身指令强制，不靠模型档位。可配置多个并[按对话切换](../system-guide/models-providers-access.md)——例行工作用便宜模型、关键节点用强模型，是合理模式。

**要花多少钱？**
软件免费开源。你向模型提供商按用量付费，按其定价——应用不加价，并
[边用边显示用量与费用](../system-guide/responses-and-controls.md#the-context-ring)。

## 关于信任

**它会编造引用吗？**
构建目标是不这样做：文献来自带 DOI 的实时学术搜索，或明确标为未核实；记忆从不当成搜索结果；「我无法核实」是正常回答。见
[搜索、来源与网页内容](../system-guide/search-sources-web.md)。
没有任何系统能使编造不可能——但在这里它违反产品明示规则，而不是流畅度可接受的代价。

**我的数据隐私吗？** / **敏感材料能用吗？**
一切本地存储；离开本机的恰好是发往你配置的模型提供商的内容，以及 Work 模式下的搜索流量。精确答案——包括可给伦理委员会的一段话——见
[你的数据与隐私](../system-guide/data-and-privacy.md)。

**AI 行为真的与其他工具不同吗？**
身份、原则与方法是仓库中的可读文件——soul、角色、技能——不是营销口号。读它们，再拿难案例检验；产品由想知道失败何时发生的人构建。

## 关于产品

**与 ChatGPT / 通用助手有何不同？**
三个结构差异：为研究判断而非讨好式回答构建的行为；你控制的 Understand/Work 边界而非一刀切的智能体访问；本地优先存储与可读、可移植格式。更完整的回答见
[Alt Theory 是什么](../start-here/what-alt-theory-is.md)。

**与 Claude Code / Pi / 编码 harness 有何不同？**
共享生态（并可[从它们导入](../system-guide/imports-and-continuity.md)），但为不同工作构建：以理解为先的研究工作，把 harness 机制包进面向学者的界面与行为模型。若你已住在 harness 里，诚实建议可能是
[插件形态](../advanced/plugins-and-capability-differences.md) 而不是应用。

**能用其他语言吗？**
对话：可以——智能体用你的语言回答。界面目前为英语；简体与繁体中文已在计划中。文档以英语为先。

**提到研究——我被研究了吗？**
没有。公共应用无遥测，不向项目发送任何东西
（[隐私](../system-guide/data-and-privacy.md)）。Alt Theory 也是关于学者 AI 支持的研究计划，与公共应用分开的是有明示同意的研究情境部署。若你有兴趣贡献：
[版本与进一步帮助](releases-and-further-help.md)。

**X 何时支持？**
[已知限制](compatibility-formats-limitations.md) 诚实列出当前边界；变更日志与发布显示什么在动。
alpha 意味着列表以真实节奏变化。

# 术语表

产品用语，定义一次。交叉引用指向各权威页。

**Understand（理解模式）** — 认真对话、触达收窄的能力模式：无命令执行、无实时网络、无项目文件夹。使用产品的完整方式，不是 Work 的预览。
[→ 理解模式与工作模式](../start-here/understand-and-work.md)

**Work（工作模式）** — 具有实践触达的能力模式：工作文件夹、实时搜索与抓取、文档产出、命令——在可见批准之下。
[→ 理解模式与工作模式](../start-here/understand-and-work.md)

**Conversation（对话）** — 使用 Alt Theory 的基本单位：一条讨论与行动的线程，自有历史、模式、模型与材料。持久、可恢复、可移植。
[→ 对话与历史](../system-guide/conversations-and-history.md)

**Branch（分支）** — 从某条消息分出的相关对话，携带到该点为止的一切，原线完整。
[→ 处理回复与对话控件](../system-guide/responses-and-controls.md)

**BTW** — 主对话旁侧栏中的旁线对话，携带当前上下文；用于题外话。可提升为分支。
[→ 处理回复与对话控件](../system-guide/responses-and-controls.md)

**Helper（帮助助手）** — 回答关于 Alt Theory 本身问题的内置助手。从干净状态开始（不读你的对话），依据当前文档作答。
[→ Helper 与应用内指引](../system-guide/helper-and-guidance.md)

**Working folder（工作文件夹）** — 附加到 Work 对话的本机文件夹；智能体可读与创建文件的场所，也是它可修改范围的边界。
[→ 工作文件夹、文件与路径](../system-guide/working-folders-files-paths.md)

**Knowledge base（知识库，KB）** — 策展参考材料，按对话可选，智能体可查阅以奠基讨论。
有别于工作文件夹。
[→ 知识库与上下文](../system-guide/knowledge-bases-and-context.md)

**Role（角色）** — 可选呈现层：语气、节奏、教学风格。改变智能体听起来如何，从不改变原则。
[→ 定制](../advanced/customization-without-changing.md)

**Soul** — 身份层：智能体的世界观与原则，任何角色都不可覆盖。可读文件，与其他一切一样。
[→ 定制](../advanced/customization-without-changing.md)

**Skill（技能）** — 塑造智能体如何处理某类任务的可读指令文件。内置技能承载产品方法；你自己的以平等身份参与。
[→ 技能如何工作](../system-guide/how-skills-work.md)

**Command（命令）** — 可从 `/` 面板按名称调用的任何东西：技能，以及 /branch、/compact 等对话操作。
[→ 命令](../system-guide/commands.md)

**Toolbox（工具箱）** — 输入区旁重点动作的短菜单；是前门，不是完整清单。
[→ Toolbox](../system-guide/toolbox.md)

**Approval（批准）** — 动作越过对话边界时显示的请求（域外读取、网络、安装）。拒绝始终安全；沉默等于否。
[→ 权限](../system-guide/permissions-approvals-agent-activity.md)

**Compaction（压缩）** — 把长对话较早轮次可见地浓缩为摘要，使对话能在模型上下文窗口内继续。
[→ 对话与历史](../system-guide/conversations-and-history.md)

**Import（导入）** — 把另一 harness（Claude Code、Codex、OpenCode、Grok Build）的对话带入 Alt Theory，成为普通、可继续的对话——忠实，损失标注而非遮掩。
[→ 导入与连续性](../system-guide/imports-and-continuity.md)

**Plugin（插件）** — 为在其他 harness 内使用而打包的 Alt Theory 资产：内置技能不变，加上以该 harness 格式承载产品身份的 agent 定义。
[→ 插件与能力差异](../advanced/plugins-and-capability-differences.md)

**Pi** — 应用所基于的开放 agent harness。对话、技能与配置遵循生态约定而非专有约定的原因。
[→ 应用与插件](../start-here/app-and-plugins.md)

**Model / provider（模型 / 提供商）** — 驱动对话的 AI 模型，以及在你账户下供应它的服务。应用与模型无关；你按对话选择。
[→ 模型、提供商与访问](../system-guide/models-providers-access.md)

**Provenance（出处）** — 按来源标注每条主张的纪律：此刻找到的（带引用）、模型记忆（标未核实），或推断（说明如此）。产品的中心诚实规则。
[→ 搜索、来源与网页内容](../system-guide/search-sources-web.md)

# 版本与进一步帮助

## 读懂发布线

Alt Theory 版本名携带成熟度：`-alpha` 标签表示活跃开发——可用、已在真实研究中使用，且仍在变动。仓库变更日志用平实语言记录每次发布改了什么，版本说明解释编号。alpha 对兼容性意味着什么——什么受保护（你的数据，始终）以及什么仍可能变（资产、界面）——在
[兼容策略](../advanced/compatibility-updates-debugging.md) 中精确陈述。

更新前，变更日志值得扫一眼；更新后，重新打开最近对话，任何回退通知会告诉你所依赖的东西是否移动了。

## 获取帮助，按远近顺序

1. **应用内 Helper** — 怎么做、在哪里、引导式设置、平实解释。依据当前文档作答，并说明无法核实什么。
2. **这些文档** — 权威功能页
   （[系统指南](../README.md#system-guide)）、按问题组织的帮助
   （[故障排除](troubleshooting.md)）、边界
   （[已知限制](compatibility-formats-limitations.md)）。
3. **仓库** — `github.com/syuan-research/alt-theory`：源码、变更日志与 issue 跟踪。

## 报告缺陷

alpha 产品以好报告的速度改进。有用的报告包括：做了什么、发生了什么、期望什么、应用版本与平台，以及涉及的对话是否导入或压缩过。
[分流步骤](troubleshooting.md#is-it-a-configuration-problem-a-provider-limitation-or-a-bug)
帮你归到正确问题类型——而「行为不诚实」（未标注主张、编造引用、静默替换）在这里始终是缺陷报告，绝不是吹毛求疵。

## 反馈与研究计划

Alt Theory 也是长期研究努力：学者究竟需要何种 AI 支持，我们如何知道？当前产品体现暂定答案，不同意见是有用数据。若你想超出「使用工具」——它辜负你的难案例、研究合作，或参与研究——经仓库联系项目。带上困难例子；那就是邀请。

# 故障排除

跨功能问题，或不明显属于某一功能的问题。功能局部问题请先看各系统指南页的核对与恢复小节——知道涉及哪个功能时那是更快的路径。

## 完全无法开始对话

几乎总是提供商链路。按
[模型、提供商与访问](../system-guide/models-providers-access.md#recovery-i-configured-it-but-it-doesnt-work)
中的清单走：提供商已保存*且*激活 → 密钥有效且有余额 → 模型 id 仍有效 →
重新打开。应用按设计在没有有效提供商时拒绝开始对话——修复在「设置 → 模型」，不在反复重试。

## 智能体似乎卡住了

先区分状态——看起来相似，应对不同：

- **在等你的批准**：有待处理批准请求——检查对话与列表中的等待批准标记。回答它；在你回答前什么都不会继续。
- **在做长工作**（大读取、慢抓取）：状态区显示活动，工具行持续出现。稍等，或**停止**并改向——停止始终安全。
- **真正卡住**（状态不动、无待批准）：停掉它，然后继续对话。若对话在同一操作上反复卡住，那是值得报告的模式。

## 搜索、抓取或读文档一直失败

- 单个页面或站点失败 → 多半是该站点（墙、反爬）：提供时试受保护抓取档，或换来源。
- 全部失败 → 工具本身：装了吗？（引导式设置流程可按请求重新核实——请智能体检查搜索工具。）网络是否过滤目标？
- 文档失败 → 见
  [文档、图像与其他输入](../system-guide/documents-images-inputs.md#recovery)：
  受保护/损坏/扫描文件各有具体答案。

## 重新打开后对话看起来不对

缺尾、渲染异常、意外模型：刷新一次，再查可见通知——过时工作文件夹、模型回退、资产回退——各自点名发生了什么、该做什么
（[参考](../advanced/compatibility-updates-debugging.md)）。带占位块的导入对话是在向你展示诚实标注，不是损坏
（[占位符含义](../system-guide/imports-and-continuity.md)）。

## 安装中途失败

设置流程会报告成功与失败了什么——没有假装。重跑（请智能体重试安装）；底层安装器可安全重复。若机器需要代理或阻止下载，那是常见原因，失败信息中的手动替代是变通办法。

## 是配置问题、提供商限制，还是缺陷？

最省时间的分流：

1. **新对话、默认设置** — 能复现吗？不能：配置问题；对照可工作的默认
   （[诊断顺序](../advanced/compatibility-updates-debugging.md#debugging-an-integration)）。
2. **同一提示、不同模型/提供商** — 是否跟着提供商走？若是：提供商限制（速率、上下文大小、能力）；修复在提供商侧或换模型。
3. **默认设置下跨提供商仍复现** — 多半是真缺陷。
   报告时写：做了什么、发生了什么、期望什么、应用版本、平台，以及对话是否导入或压缩过。
   [在哪里报告](releases-and-further-help.md)。

## 答案是「应用还做不到」时

在调试「其实是边界、不是故障」的东西之前，先看
[已知限制](compatibility-formats-limitations.md)——扫描 PDF、修订痕迹输出、云文档等列在那里并附诚实状态。

# 兼容性、更新与集成调试

维护页：alpha 期间更新可能改什么，以及如何诊断不再正常的集成。

## alpha 兼容策略，诚实说

在首个非 alpha 发布前，产品对自己持守这些规则：

- **用户数据从不会因更新受损。** 对话、记录及其出处始终保留。此承诺没有 alpha 星号。
- **资产仍可能变化。** alpha 构建可能重命名或移除内置资产（角色、soul、技能）。记录的资产在当前构建中不复存在时，对话回退到当前默认——**可见地**：重新打开时显示通知，点名记录了什么、现用什么。静默替换视为缺陷。
- **界面与配置仍可能移动。** 发生时发布说明会写。

从首个稳定版起，记录的资产跨更新持续解析；届时本节将修订。

## 更新

- **打包应用**：安装新构建；数据目录与应用分离，原样延续。
- **源码构建**：拉取、重装依赖、重建，并重跑后端测试作诚实检查。
- **任何更新后**，值得一分钟：扫一眼变更日志，重新打开最近对话（若你用过的东西被重命名，资产回退通知会出现在此），若依赖优先级行为则检查「设置 → 技能」。

## 调试集成

当定制设置行为异常——技能不再触发、模型表现与昨天不同、对话加载了意外资产——应用保留足够记录，按对话回答*实际发生了什么*：

- **加载了什么**：每条对话在创建时记录组装的确切资产——soul、角色、KB、技能及其来源（内置 / 你的 / 项目）、模型与提供商——带内容哈希。「本对话实际拿到了我技能的哪一版」有存储答案。
- **此后改了什么**：配置变更与恢复时回退作为事件与对话一起记录，因此创建至今的漂移可检查，而不是推断。
- **它做了什么**：转录的工具行本身就是日志——每次读、命令与技能加载，按轮次。

可行诊断顺序：

1. 在**新对话**中复现——多数「变了」报告是陈旧打开对话 vs 新对话设置。
2. 对照期望检查对话的**已加载资产记录**（对的技能？对的来源？对的模型？）。
3. 检查「设置 → 技能」中的**优先级与启用**（按模式！）。
4. 检查**应用外的生态**：harness 共享技能文件夹变了吗？提供商下线了模型吗？附加文件夹中的项目技能在遮蔽全局技能吗？
5. 然后才怀疑构建——并把复现带到
   [报告](../help/releases-and-further-help.md)。

## 回滚

- **资产与技能**：它们是文件——把自己的放在版本控制下（`~/.agents/skills` 的 git 仓库几乎零成本），回滚就是 checkout。
- **应用**：打包构建可重装旧版；源码构建检出上一标签。数据目录在 alpha 线内前向兼容；回滚应用不会回滚你的对话。
- **已迁移配置**：迁移副本是普通配置文件——引导流程可重跑，先前状态就是实验前提供商文件所说的（实验时请保留副本）。

# 跨 harness 工作与连续性

Alt Theory 把对话当作可移植工作，而不是被俘获的数据。本页覆盖在应用与其他 agent harness 之间双向、深入地移动工作。

## 会话主体与 Pi 兼容

Alt Theory 对话以 Pi 的 JSONL 会话格式存储——应用刻意没有发明第二种转录格式。后果：

- 本地 Alt Theory 对话可导出为 Pi 可继续的形式，兼容的 Pi 会话也可进入；
- 转录比产品活得更久：对话历史在你磁盘上的文档化、广泛实现格式中，不是专有存储；
- *不是*对话的应用级东西——显示状态、研究记录、应用元数据——住在会话主体旁，不在其内，使主体保持干净便于交换。

## 导入，进阶用户想要的深度

[用户级页面](../system-guide/imports-and-continuity.md) 覆盖流程；这里是底层机制，在推边界时值得了解：

- **三种表示在每次导入中保持区分**：*可见转录*（人应看到的）、*活动上下文*（模型实际向前携带的）、以及*原始源证据*（其余一切，保留且可搜索，从不重放）。把它们混在一起就会编造历史；分离是 Alt Theory 不这样做的原因。
- **在任何东西存在前完整预检**：先解析并验证整个源；只有通过的投影成为会话。失败是结构化拒绝，点名记录与理由。
- **声明的转换**：每步有损操作与会话一起记录，转录中的占位符写明未重放什么。
- **按来源诚实**：例如加密的源压缩摘要不会解密或改写——续写从可读后缀开始并标注限制；谱系无法确定的源被拒绝而非猜测。子/子代理转录作为可搜索证据归档索引，不作为主历史重放。
- **重复导入分类**为未变（重新打开已有导入）或已变（新的托管副本）——变化的源从不合并进你的续写。

## 在别处继续应用对话

反向：在 Pi 中继续的 Alt Theory 对话保留对话主体，但留下应用层——Understand/Work 强制、批准 UI、应用资产是应用的事。agent 身份仅在你带来时旅行（见
[插件](plugins-and-capability-differences.md)）。向人或非 harness 工具交接时，markdown 摘要与 HTML 导出是正确载体——可读，但不是续写格式。

## 什么带走、什么留下，一表说清

| 事物 | 跨表面携带？ |
|---|---|
| 对话主体（轮次、工具、图像） | 是 — Pi 兼容 JSONL |
| 压缩摘要 | 是，源中可读时 |
| 技能 | 是，经共享技能位置（[细节](shared-configuration-and-assets.md)） |
| 模型/提供商配置 | 否 — 各工具自有；经引导式设置一次迁移 |
| 模式、批准、应用设置 | 否 — 应用层 |
| 应用级记录（显示状态、出处） | 留在应用副本 |

## 现实的多 harness 工作流

在一处想，在另一处做：导入分析成形的 Claude Code 会话，在 Understand 中用知识库审视，在工作文件夹的计划记录中发展设计，再回到编码 harness 继续实现——计划记录与任何文件在项目文件夹中，两边都可见。工作文件夹，而不是对话，是 harness 之间的自然共享地面；把持久状态放在文件里，任一侧都能捡起。

# 不改动 Alt Theory 的定制

人们对 Alt Theory 想改的大部分东西，并不需要碰应用本身。产品行为刻意承载在可读资产中——技能、角色、soul、知识库、模型配置——每一层都可由你扩展。

## 你自己的技能

最大的定制面，权威说明见
[添加与管理技能](../system-guide/add-and-manage-skills.md) 与
[共享配置](shared-configuration-and-assets.md)。简版：写 `SKILL.md`，放到共享或项目技能位置，若与内置方法重叠则设优先级。技能可编码从「我的学科如何引用」到完整分析工作流的一切。

## 角色

**角色预设**改变智能体如何呈现——语气、节奏、苏格拉底式还是直接、突出哪些思考动作。作为 markdown 文件加入应用的角色预设资产文件夹（kebab-case slug，按文件名选择）；会出现在角色选择器中。

使角色可自由书写的边界：角色改呈现，从不改原则。身份层（soul）明确高于任何角色——「要鼓励」的角色不能压过事实优先于附和。你可以写严苛批评者或耐心导师，而不会变成不同产品。

## Soul

**soul** 是身份层本身——世界观与原则。它像角色一样可选（「无」也可选），文件与其他一切一样在仓库中可读。写替代 soul 在机制上受支持，但会从根上改变产品性格——对多数定制目标，角色或技能才是对的工具，默认 soul 就是产品。

## 知识库

添加领域：在应用 KB 资产下创建 markdown 材料文件夹，即可在 KB 选择器中选。好知识库是策展的，不是倾倒的——智能体按判断查阅，信噪比决定查阅是否有用。领域元数据可声明范围与预期用途，便于智能体用得好。

## 自定义指令

按对话的常驻指令——你坚持的术语、领域要求的格式——可作为指令资产添加，在对话设置时选择，位于身份层与对话之间。

## 模型与提供商

任何兼容 API 的提供商都可在配置中添加——包括本地模型服务器，与
[隐私姿态](../system-guide/data-and-privacy.md) 自然组合：本地模型意味着对话内容不离开任何地方。模型条目声明应用会尊重的能力（如图像输入）。

## 界线在哪

以上一切都是数据：加入资产文件夹与配置的文件，升级安全且可分享。一旦你想要不同的*应用本身行为*——新工具、不同模式边界、UI 变更——你已越过定制，进入
[修改 Alt Theory](modifying-alt-theory.md)。

# 修改 Alt Theory 及其扩展边界

Alt Theory 开源——软件 MIT，原创文档与 agent 资产 CC BY 4.0。你可以阅读、构建、更改全部。本页关于接缝在哪：设计预期哪些变更，哪些意味着你在维护 fork。

## 为变更设计的接缝

按你伸手多远的大致顺序：

1. **资产** — 技能、角色、soul、知识库、指令
   （[上一页](customization-without-changing.md)）。是数据，不是代码；升级安全。
2. **配置** — 提供商、模型、按模式技能启用、优先级。同样升级安全。
3. **底层 Pi 生态** — 应用嵌入 Pi agent 运行时，因此以 Pi 生态资源存在的能力（包、扩展、工具）是新 agent 能力的预期路径——在那里构建或采用，而不是教应用核心新把戏。
   两个边界成立：包必须使用嵌入运行时的库（要求不同 Pi 核心的包会被禁用并有可见诊断，不会静默加倍），且应用安全层始终在回路中——无论哪个扩展提供了工具，它都中介工具执行。
4. **应用本身** — 后端、前端、打包。任你改（MIT），并诚实承担后果：你拥有与上游变动的合并，alpha 阶段变动很快。

## 扩展姿态，直说

两个有意决定塑造以上一切：

- **无环境漫游式扩展加载。** 应用不会自动加载环境中存在的任意扩展；扩展仅在应用显式注册处加载。这是安全与可预测决策——对话的能力是其配置所说的，不是机器上碰巧装了什么。
- **受信任软件边界。** 扩展与工具以你的用户权限执行。策略层约束*操作*，但没有任何策略能使未受信任的扩展安装变得安全。你往运行时加什么，就是在信任什么——请据此审计。

## 源码构建的实践说明

- 仓库 README 载有当前构建/测试命令
  （[安装页](../start-here/install-and-launch.md) 有简版）。
- 后端测试套件与前端类型检查是变更后的快速诚实检查；用修改后的构建做真实工作前请先跑。
- 架构文档在仓库 `development/architecture/` — 正是为这类读者写的。
- **源码布局与代码结构**问题，请指向公共 GitHub 仓库（`syuan-research/alt-theory`）及其中的
  `development/architecture/`——不要只靠应用内 Helper 文档。
- **纯 agent harness / Pi 引擎**行为（包、TUI 习惯、底层会话协议），用 [Pi](https://pi.dev) 文档。Alt Theory 嵌入 Pi；产品特定策略与 UI 留在这些文档中。

## 若你构建了什么

资产层设计为可旅行（尤其技能——跨 harness 可用）。若你构建的技能、角色或知识库超出自己的设置有价值，分享成本只是一个文件夹。对产品本身的变更，仓库的贡献指引是入口；alpha 阶段产品最受益于描述真实研究使用的 issue。

# 插件与能力差异

本页面向在应用与插件形态之间做选择、或两者并用的读者。假定你了解自己的 harness。

## 插件形态究竟是什么

插件是把 Alt Theory 的资产转换到你 harness 的标准——不是应用的移植：

- **内置技能，不变。** 技能在遵循标准技能约定的 harness 之间通用；你得到的方法文件与应用随附的相同
  （[目录](../system-guide/bundled-skills.md)）。
- **以你的 harness 格式写的 agent 定义** — harness 声明 agent 人格/子代理的方式——内容承载 Alt Theory 的身份与原则（soul 与角色材料）。
- **可选知识库**：你放在 harness 可读位置的 markdown 材料，由 agent 定义引用。

你买到的是：Alt Theory 的工作方式——有出处纪律的搜索、宁拒不编、方向设定前对齐、计划记录、克制编辑——在你已经工作的工具里。

## 能力差异

| 能力 | 应用 | 你 harness 中的插件 |
|---|---|---|
| 以理解为先的行为（soul、原则） | 内置 | 经 agent 定义 |
| 内置方法技能 | 内置 | 相同技能，安装到你的 harness |
| Understand/Work 模式边界 | 应用强制 | 改由你 harness 的权限模型 |
| 批准 UI 与策略层 | 应用的 | 你 harness 的 |
| 搜索/抓取/转换工具 | 经技能捆绑的 CLI 工具 | 技能使用你 harness 同类原生工具，或环境中已有的相同 CLI |
| 知识库选择器、角色 UI | 应用 UI | 手动：自行放置并引用材料 |
| 对话列表、分支/BTW/Helper UI | 应用 UI | 你 harness 自己的对话功能 |
| 从其他 harness 导入 | 应用功能 | 不包含 |

一个诚实的细微处：*方法*技能（search-policy、aligning、plan-record、precise-edit、conventions）作为纯指令迁移。三个工具驱动技能（web-search、page-fetch、doc-convert）作为文件迁移但规定特定命令行工具——需在宿主环境安装，或由 harness 同类原生工具替代。search-policy 有意在任何情况下可移植：它命名所需工具的*种类*（通用搜索、可读抓取），从而约束 harness 中匹配的工具。

## 什么不迁移

模式边界值得明确：你 harness 的权限模型取代 Understand/Work。若 harness 默认有宽工具访问，插件的 agent 定义带来 Alt Theory 的*判断*，但不带来应用的*强制*——请配置 harness 自身权限以匹配你想要的姿态。

## 选择，以及两者并用

- 你要的是方法，harness 是你日常所在 → 插件。
- 你要强制的思考环境、研究表面、UI——或向非 harness 同事推荐产品 → 应用。
- 两者：正常且支持。装在共享跨 harness 位置的技能同时服务应用与 harness，对话可
  [在其间移动](cross-harness-work.md)。

## 可用性

插件打包跟踪应用发布线；查仓库了解当前各 harness 安装说明，以及当前打包了哪些 harness 格式。

# 共享配置、技能、模型与资产

当 Alt Theory 与 Pi 或其他 harness 并存时，实践问题是归属（谁拥有哪份配置）、发现（从哪读什么），以及优先级（同名之物谁赢）。本页精确陈述三者。

## 归属（Ownership）

- **Alt Theory 拥有**：其模型/提供商/认证配置、应用设置（技能启用、优先级、自动标题）、内置资产（技能、soul、角色、知识库），以及对话数据。
  全部在自己的应用目录。
- **Alt Theory 不拥有但读取**：共享跨 harness 技能位置（`~/.agents/skills/`），以及已附加工作文件夹内的项目资源（项目技能、agent 上下文文件）。
- **Alt Theory 从不触碰**：其他 harness 的配置主目录。它不把运行时指向 Pi 的配置目录，也不同步。把现有 Pi/OpenCode 设置带过来是**一次性、有引导的迁移**——Helper 与你一起检查现有配置，可见地复制有用部分到 Alt Theory 自己的文件。

底层设计规则：就地读取生态资源，拥有自己的状态，从不镜像他人的。

## 发现

对话实际加载什么，按来源：

| 来源 | 加载什么 | 何时 |
|---|---|---|
| 内置（`agent-assets/`） | Alt Theory 技能、soul、角色、KB | 始终（受模式与启用约束） |
| 你的应用级启用 | 你按模式启用的外部技能 | 按技能设置 |
| 共享跨 harness 目录 | `~/.agents/skills/` 中的技能 | 启用时 |
| 已附加工作文件夹 | 项目技能（`.agents/skills/`、`.pi/skills/`）与项目上下文文件 | Work 模式，附加期间 |

每条对话在创建时精确记录加载了哪些资产及来源——使「为何那样表现」后来可答
（[检查](compatibility-updates-debugging.md)）。

## 优先级

两层机制：

1. **优先级设置**（全局，三选一）：优先 Alt Theory 内置技能、优先你的，或冲突时询问。默认：prefer-bundled。「冲突」指同类别方法——两个搜索技能、两个文档技能——不是任意两个技能。
2. **技能文本让位**：与设置无关，若干内置技能明确让位于同类别的用户安装技能（文档转换、页面抓取、搜索）——更丰富的领域替换正是预期情况。

对非技能资产无需解决冲突：模型配置是 Alt Theory 自己的；角色或 soul 是对话所选；项目上下文文件全部加载（它们描述不同事物，智能体像任何项目文档一样权衡）。

## 把你的技能与内置方法组合

认真定制设置的预期模式：

- 让**横切方法技能**（search-policy、aligning、plan-record、conventions）做它们的工作——它们刻意薄且领域中立。
- 用**你的领域技能**承载实质：你领域的文献实践、方法传统、写作约定。它们与方法层组合而不是打架——search-policy 管*诚实*，你的技能管*在你领域什么算好来源*。
- 当真不同意某内置方法时，替换它（优先级：优先你的），而不是绕开它。

## 模型

模型与提供商配置以 Pi 兼容文件存在 Alt Theory 目录内——格式共享，文件不共享。实践效果：提供商设置易于双向迁移（引导式迁移直接读 Pi 文件），为 Pi 写的模型定义复制后即可用，你在 Alt Theory 中做的任何事都不改变 Pi 安装使用什么。

### 两个目录，以及如何在其间移动

| | Alt Theory（本地应用） | Pi |
|---|---|---|
| 配置目录 | `~/.alt-theory/pi-agent/` | `~/.pi/agent/` |
| 提供商与模型 | `models.json` | `models.json` |
| 密钥与登录 | `auth.json` | `auth.json` |

Alt Theory 从不自行读取 Pi 目录。`models.json` 每个提供商一条——名称、Base URL、API 类型
（`openai-completions`、`openai-responses`、`anthropic-messages` 或
`google-generative-ai`），以及模型列表；`auth.json` 为每个提供商名保存凭证。两者都是普通可读 JSON。

**从 Pi 迁移提供商**（Helper 与你一步步做，而不是一次不透明搬迁）：

1. 读 Pi 的 `models.json` 中该提供商条目——名称、Base URL、API 类型，以及你实际用的模型。
2. 把同一条目加入 Alt Theory 的 `models.json`，或在「设置 → 模型」重填，后者写同一文件。
3. 从 Pi 的 `auth.json` 复制该提供商凭证到 Alt Theory 的，使用同一提供商名。
4. 从应用确认：提供商出现在「设置 → 模型」，对话可在其某个模型上开始。

任一步都不会回写 Pi。若提供商在 Pi 中通过登录流程而非密钥连接，在设置中重跑登录比复制令牌更可靠。
