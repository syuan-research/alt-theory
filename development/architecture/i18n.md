# Architecture: Language Support (v1.3.0-alpha.6)

## Mechanism

- `t("English source string", params?)` — the English text IS the catalog
  key; a missing key returns the English. Interpolation is plain `{name}`
  replacement. No i18n library.
- **New friend-facing UI strings must land in both `zh-Hans.ts` and
  `zh-Hant-HK.ts` in the same change** (or immediately after via
  `scripts/i18n-sync.mjs`). Shipping `t()` with English-only catalogs is a
  product regression for Chinese UI, not “auto fallback.”
- Locales: `en` (identity), `zh-Hans`, `zh-Hant-HK`. Catalogs are flat
  `Record<string, string>` files in `alt-theory-app/frontend/src/i18n/`,
  GENERATED by `scripts/i18n-sync.mjs` and committed.
- Frontend: `src/i18n/index.ts`. The catalog loads ONCE before any app
  module evaluates — `main.tsx` awaits `initI18n()` and then dynamically
  imports `App` (some modules call `t()` in module-level constants).
  Changing the language saves the setting and reloads the page; there is no
  re-render plumbing.
- Backend: `web-server/i18n.ts` imports the SAME catalog files. Language is
  module state (`setBackendLang`), set at server boot from app settings and
  on `PUT /api/settings/lang`. Single-user local app assumption.

## Language selection

- App setting `lang` (`auto | en | zh-Hans | zh-Hant-HK`, absent = auto) in
  `app-settings.ts`, routes `GET/PUT /api/settings/lang`, Settings →
  General → Language card. `auto`: frontend follows `navigator.language`
  (`zh-HK`/`zh-TW`/`*hant*` → zh-Hant-HK, other `zh*` → zh-Hans); backend
  treats auto as English.
- Conversation language is untouched — the assistant follows the user's
  input language natively.

## Translation policy

- **Model-facing text is never translated**: tool results, agent-mail
  bodies/context fragments, prompts. Only text whose sole audience is the
  user goes through `t()`. Transcript agent-team lines translate the
  from/event prefix only; the body is shown verbatim (it is model context).
- Help docs (`alt-theory-help/references/docs/`) are Helper-agent context
  and stay English; the Helper answers in the user's language. (Doc
  translation is deferred until doc content stabilizes, for the website.)

## Sync tool

`node scripts/i18n-sync.mjs [--check]` — extracts every `t("…")` key from
frontend and web-server sources, translates keys missing from zh-Hans via
the `deepseek-official` provider configured in `~/.alt-theory/pi-agent/`
(override: `I18N_BASE_URL/I18N_API_KEY/I18N_MODEL`), derives zh-Hant-HK
from zh-Hans with HK written-usage rules, prunes orphaned keys, rewrites
both catalogs sorted. Glossary and style rules: `scripts/i18n-glossary.md`.
Hand-edits to catalogs survive (only missing keys are ever translated);
`--check` exits 1 if catalogs are out of sync with the source.
